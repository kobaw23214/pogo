# 浏览器任务评测 v1

2026-10-01。本阶段增加可复现的任务集、真实模型入口和可回看报告，作为后续改善 browser-use 的依据。结果衡量受控任务上的表现，不表示达到公开基准的 SOTA，也不替代真实网站、账号和长任务评测。

## 测什么

首批包含 10 类、每类 2 个变体：搜索筛选、跨页面报价比较、仅一次表单登记、分页汇总、SPA 状态更新、多标签信息整合、跨源 iframe、开放 Shadow DOM、延迟库存加载和购物车结算。页面数据由种子和任务 ID 决定；每次重复创建独立状态和随机入口地址。

任务明确要求最终 JSON 答案，判分器同时核对实际网页访问、筛选或服务端业务记录。例如登记任务必须确实生成一条且仅一条记录，提交字段正确，并返回实际回执。模型说“已完成”、工具返回 `ok`、页面截图看起来正确，都不能单独让任务通过。模拟结算使用测试 credits，没有真实支付。

判分规则、答案和参考操作脚本只存在评测进程内存中，不通过网页或 HTTP 接口提供，也不会发给模型。

## 执行链路

`Node 任务调度 → 独立 Go Agent 子进程 → 项目 browser 工具 → 本地记录网关 → 原生 worker → Playwright/Chromium → 测试网页`

Go 入口复用项目的 `config.Resolve`、LLM 客户端、Agent 循环和 browser 工具，仅注册浏览器工具。使用固定评测 system prompt，记录 prompt hash 与模型元数据。这是 `pogo-agent-browser-only` profile，**不是完整生产对话提示词的端到端评分**：不加载业务 Skill、历史对话、AGENTS、其他工具或视觉辅助模型。

LLM 调用保留项目配置的模型、请求兼容设置、额外参数及请求头；基线关闭客户端自动重试，API 失败保留为结果。截图通过内存 ImageResolver 交给支持图像的模型，文本模型不会收到图像像素。项目当前将 `glm-5.3` 配置为 `vision:false`，因此其结果应解释为 DOM 交互基线。

每轮评测启动独立本机 worker 和 Chromium，每项任务使用全新的 BrowserContext，结束后要求清理 ACK。清理失败会停止后续任务。网页请求限制为该次测试站点，模型只有 browser 工具；它不能访问生产网页、工作目录或判分 API。模型 API 请求由 Go 客户端独立发出。Chromium 不继承模型密钥环境。

报告记录 Node、Playwright、Chromium 版本及宿主平台和架构。本机 macOS/arm64 运行的成绩不能当作 Linux Docker 的性能实测；生产镜像仍需单独验收。

这套隔离用于受控评测；可信本地适配器进程本身并非多租户系统沙箱。生产的身份、BrowserGate 授权和人工接管仍由其原有集成测试覆盖，本基线绕过 Web 会话入口。

## 成绩口径

| 字段 | 口径 |
| --- | --- |
| 主成功率 | 通过任务数 / 本轮计划任务总数。超时、异常、预算用尽和未运行都留在分母中 |
| 通过 | 业务判分通过，且正常完成；超预算后已经满足业务条件仍不计通过 |
| 参考验证 | 参考脚本通过率单独标示，模型 `success_rate` 为 null，不能当作模型成功率 |
| 耗时 | 从单项创建上下文到执行结束，包含初始导航、截图和模型等待；不包含最终上下文清理 |
| steps | worker 回执确认已尝试的原子步骤，batch 只计实际返回的子步骤，失败步骤也可被计入 |
| requested_steps | 请求的原子步骤数，未执行的 batch 尾部仍消耗请求预算，防止预算绕过 |
| tool_calls | 到达记录网关的 browser execute 调用数，不等同模型轮数；初始导航属于环境准备，不计步数 |
| 人工干预 | 本轮不提供人工协助，`human_interventions=0`；遇到待处理弹窗另记 `human_requests` |
| 重复提交 | 业务记录中超出允许次数的实际提交；不能依靠模型自报 |
| tokens | 服务商实际返回的 input/output 等计数。未知用量为 null，异常/取消可能存在未结算请求时标 partial |
| 费用 | 仅按已配置价格和已报告用量计算；未知价格为 null，不把它写成免费或推断币种 |

默认每项 35 个请求步骤、40 个 Agent 轮次、100,000 input+output tokens、180 秒；并发 2。逐项时间和 token 控制、关闭自动重试属于本基线协议，不应在比较模型时静默改变。每次 token 限制根据返回的用量判定，正在执行的最后一个模型调用可能超额；超额响应里的工具调用不会继续执行。超时会取消 browser，外部 watchdog 允许 20 秒收尾后终止该适配器的进程组。

可选总量参数只控制是否启动下一项任务，已运行的并发任务保留各自额度。未启动任务保留在成绩分母中；报告另有 attempted 指标，但不能用它掩盖未完成任务。

错误分类根据最后的执行错误和结束状态进行启发式归类。应结合逐步回执与截图复核原因，而不是把自动类别直接当成模型根因结论。

## 报告与复现

运行方法见 [评测 README](../browser-runtime/eval/README.md)。输出包含：

- `report.html`：无需外部网络的汇总、分类结果、逐项操作和截图。
- `summary.json`：任务定义标识、种子、重复序号、运行限制、成绩、模型/用量元数据，以及源码和实际适配器二进制 SHA-256。
- `traces/*.json`：模型工具事件和浏览器回执；不记录隐藏思考文本。
- `frames/*/*.jpg`：可获取的初始画面和 browser 调用后的实际截图；画面采集为尽力记录，并非每个子动作都有一帧。

源码标识包含工作区文件哈希，因为本项目可能存在尚未提交的改动，不能只用 HEAD 声称复现。报告不会打包源码；长期复现仍需保存对应的源码和锁文件。密钥、鉴权头和截图 base64 从结构化 trace 中排除，截图单独存储。默认产物不进入 Git 或镜像。

必须先完成两类无模型验证：参考操作通过全部任务，空操作加“我已完成”的假答案被全部拒绝。随后再用指定模型运行；不同模式、模型、种子或限制的结果分开保存，已有输出目录不会覆盖。

## 异步动作观察改造后的对照（2026-10-01）

本轮处理能力改造后剩下的两类中途错误，以及“动作回执取得太早”的问题：提交后的回执、延迟加载、SPA 重绘和弹出标签常常要模型再花一轮 wait、snapshot 或 tabs 才能看到。改动如下，具体契约见[运行时文档](native-browser-runtime.md#异步动作观察2026-10-01)：

- worker 在 agent 的 click/type/select/press/hover/scroll/navigate 之后，有界等待该动作发起的文档加载和 fetch/XHR 应答，再留短暂静默窗口，然后返回观察。默认上限 2 秒，且不超过动作超时的一半。只等待、不重试。回执新增 `settle_ms`；到上限仍未完成时给 `pending_requests`；动作打开新标签时给 `opened_tabs` 与 `from_tab`。
- Go `browser` 工具在审批和执行前校验参数：带 `actions` 却缺 `action` 时直接给出 `{"action":"batch",...}` 的改法；batch 子项缺 action 时指出第几步；wait 只给 `seconds` 时说明它只是上限，并给出 text/gone_text 用法。`actions` 字段说明改为必须配合 `action:"batch"`，文本模型 browser 声明从 3,892 增至 3,914 字节。
- worker 拒绝缺 `text` 的 type/select（原先会把字段清空），整批零执行。

系统提示词、任务与判题器指纹、种子、预算、并发和宿主运行时与前两轮一致；对比器的协议核对全部为 same，只有源码、适配器和工具声明指纹变化。

第一次运行（settle 首版）暴露了一个实现问题：fetch 以 Playwright 的 `requestfinished` 作为完成信号，而页面不读取响应体的请求（tabs 夹具的 `/visit` 打点，`Cache-Control: no-store`）在 Chromium 中可能一直不报告完成。4 次弹出标签点击因此都等满 2 秒，并误报“仍在加载”，模型随后多做了复核。修正为 fetch/XHR 收到响应即算已应答，文档请求仍等加载完成，并补了回归测试，然后完整重跑 20 项（settle 修正版）。两次结果都保留，没有挑选或替换单项记录。
