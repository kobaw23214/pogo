# Agent 内部工作流

内部工作流归属于当前用户与某个 Agent，同一 Agent 的不同聊天可以复用。产品只保留这一套工作流，层级为“用户 → Agent → 工作流 → 版本 → Run”；账号、Agent、工具和数据的原有授权继续生效。

原管理端平台工作流及其编辑、运行、多人审批、发布嵌入和后台回调已移除。旧平台工具名仍作为不可冒充的保留名称，不能恢复调用权限。普通 Agent 对话嵌入、后台任务、定时计划与条件监听独立保留；旧平台定时计划不会转换成普通 Agent 任务。

## 使用

有权管理者在目标 Agent 的能力配置中勾选内置 `agent-workflows` Skill（中文别名“内部工作流”“我的工作流”），保存后联动启用 `agent_workflow_read`、`agent_workflow_edit`、`agent_workflow_enable`、`agent_workflow_run`。关联工具以英文名称显示，勾选状态由 Skill 决定，不能单独修改。取消该 Skill 会一起停用这四个工具；文件写入等通用工具仍须单独配置。

旧 Agent 保留原有工具权限和历史，不会因为内置 Skill 曾被默认勾选而自动扩权。旧配置的部分授权会明确显示；有权用户主动切换对应 Skill 后，该组才采用完整的关联规则。服务端同样执行此规则，不能通过直接修改请求中的工具数组绕过。

在该 Agent 的聊天里描述需求，例如：

> 帮我建立资料整理流程，输入主题。先阅读我选择的资料，整理有出处的要点并写入 notes.md；等我确认和补充意见；再根据要点与意见生成 report.md。保存草稿并检查，用独立资料试跑，暂不启用。

右侧“后台任务”下面的“工作流”打开当前 Agent 的私人流程面板。聊天负责创建和局部修改，面板显示真实定义、版本、校验与运行记录。已选流程可以回到对话中修改；试跑输入区选择参数与相对当前聊天工作目录的材料文件，每行一份。试跑会真实调用模型和工具。

本人确认在流程面板完成，可填写意见；模型没有代替本人确认的工具。确认继续同一 Run；工具调用审批仍由真实执行会话的审批卡处理。流程个人确认不等同组织审批，也不能免除工具审批。

启用要求精确草稿 revision/hash，形成不可变内部可执行版本；随后修改草稿不影响启用版本或历史 Run。停用/归档禁止新启动，活跃 Run 需单独取消。显式重试创建带 retry_of 的新 Run，沿用原定义和冻结输入；外部影响不会因取消或重试自动撤销。

## 上下文按需加载

勾选该 Skill 后，普通对话不会一开始就带上这四个工具的声明。系统提示里只有 Skill 目录条目和一句固定的加载提示；模型读取这份内置 `SKILL.md`，或用户用 `/skill:agent-workflows`、Skill 卡片显式调用后，下一次请求才声明这四个工具。之后在这次对话中一直保留，会话重载后仍按历史判断；历史里已经调用过这些工具时也始终保留。压缩时这份 Skill 的正文会作为 Skill 块恢复到续写消息里，工具组随之保持声明；只有 Skill 太大无法恢复时才会重新隐藏，模型再读一次 Skill 即可恢复。

加载提示的文字只取决于会话里有哪些可延迟的工具组，与是否已加载无关，所以加载前后系统提示逐字节不变。四个声明加载后追加在工具列表末尾，而不是插回注册顺序中的位置，按最长公共前缀缓存的服务端（例如本地 vLLM、SGLang、llama.cpp）可以复用之前的全部声明。

隐藏只影响模型看到的声明，不影响授权：工具仍在该会话中注册，被按名调用时照常校验、审批和执行。没有可信发现途径时不隐藏，例如旧 Agent 有工具授权但会话里没有这份内置 Skill。模型看到的声明对重复结构只写一次并互相引用（四个工具合计约 26 KB，原为 89 KB），执行前仍按完整、封闭的 schema 校验。

`SKILL.md` 包含所有操作都要遵守的规则，以及搭建、修改 agent/confirm 顺序流程所需的说明；graph 分支、代码节点、集合迭代与循环放在 `references/` 下按需读取。读取 references 下的文档与其他 Skill 的参考文档一样，会被引用检查当作资料读取。

## 结构与执行

支持 Agent、本人确认、Python/JavaScript 代码、条件分支、并行、汇聚、集合迭代和有界循环。一个流程最多 200 个节点，最多 10 个 Agent 节点并发。节点有稳定 id，支持输入参数、已授权 Skill/快捷方式和产物引用；编辑画布布局与执行版本分别保存。详细搭建规则见内置 `agent-workflows` Skill 及其 `references/`。

权威定义、版本、编辑回执、Run、确认命令与执行段保存在现有 runs.db 的独立 `agent_workflow_*` 表中；受理和确认续段与任务队列在同一事务内提交。每次读写同时校验用户与 Agent，不以客户端筛选或模型传入身份作为授权。

一条逻辑 Run 对应独立的完整 Studio Web 执行会话。每个 Agent 步骤有自己的实际模型执行记录，保留所选 Skill、MCP、文件和工具审批能力。主聊天不被占用，关闭面板不取消运行；执行会话在普通聊天列表和搜索中隐藏，只从流程记录打开。该会话不能自由发消息、换模型、改审批策略或再创建后台流程；不注册子 Agent、监控和后台调度工具，避免脱离步骤的工作在完成或取消后继续修改产物。

流程确认点持久化后释放队列槽；本人确认由精确 run_id/step_id/命令键受理，重复点击不重复推进，再由新执行段续跑同一 Run。已持久完成的步骤不重放。服务重启时正在执行、结果未知的步骤标为中断待核查，不自动重跑。现有工具审批等待仅在进程内存中，不能跨服务重启恢复原工具调用。

Run 保存非凭据的 Agent 能力指纹；步骤和续跑前检查模型、指令、工具、Skill 与 MCP 定义。配置变化或授权撤销会阻止继续，不会自动扩大旧 Run 权限；需重新校验并发起新运行。

## 输入与产物

受理时从当前用户根目录安全解析材料，最多16份、每份4MiB、总计16MiB，复制到独立 Run 工作目录并记录 SHA256。源文件后续修改不影响已受理输入；冻结输入被改变时不继续执行。拒绝通过父目录符号链接访问其他用户的数据。

output_file 要求实际产生受限普通文件，不能只靠模型声称完成。完成后在宿主管理的独立目录保存产物快照和 SHA256；后续步骤或用户修改工作文件不改变历史产物。预览按 step_id 解析，不能指定任意路径。快照损坏会明确拒绝读取。

## 本地验证边界

使用独立临时账户、Agent、聊天、文件和数据库验证。关键验收包括自然语言建改、真实工具与报告、同 Run 本人确认、确认点重启恢复、幂等与并发、跨用户/Agent 隔离、权限撤销、取消重试、文件路径与快照完整性。组织审批、跨 Agent 流程编排、工作流对外发布嵌入和流程定时触发不属于当前内部工作流的能力。每次发布实际执行的检查与验收范围，以该次发布记录为准。
