# 界面国际化

Pogo 的界面支持简体中文（`zh-CN`）、繁体中文（`zh-TW`）、英语（`en`）、日语（`ja`）、韩语（`ko`）、德语（`de`）、法语（`fr`）和西班牙语（`es`）。

语言选择在“外观与语言”和对话侧栏中提供，保存在当前浏览器的 `pogo-locale`。首次访问会依次匹配浏览器首选语言：如 `ja-JP` 对应日语，`zh-Hant`、`zh-HK` 对应繁体中文，`zh-Hans` 对应简体中文。不支持的语言回退英语。界面更新 HTML 的 `lang` 属性，并将选择传给组件库和宿主请求。

语言包均为本地资源，切换时不调用在线翻译。用户输入、Agent 名称与指令、自定义 Skill/MCP 描述、模型回复、文件和网页内容不会被自动翻译。内置工具和内置 Skill 的展示说明单独本地化，不改变执行定义。

## 代码组织

- `web/ui/src/i18n/locales.ts`：支持的语言、母语名称、语言匹配。
- `web/ui/src/i18n/index.ts`：消息装载、英语回退、偏好保存、`getLocale`、`setLocale` 和非组件使用的 `gt`。
- `web/ui/src/i18n/messages/*.ts`：按模块维护简中、英文的源消息。
- `web/ui/src/i18n/locales/*.json`：六种新增语言的完整消息表。
- `web/ui/src/api/hostErrorCopy.ts`：识别宿主已知错误模板，保留路径、名称、数值等动态参数及原始诊断。未知或外部错误不做猜测翻译。
- 工作流、Skill 和 Office 状态使用已知宿主 code/固定原因映射；可展开的技术详情保留原始信息。

## 增加或修改文案

1. 给对应模块添加简中、英文消息，再同步六种语言的相同键。使用语义键和完整句式，例如 `deleteAgent: "Delete {name}?"`；不要拼接几段译文组成一句话。
2. 模板使用 `useI18n().t`；非组件的展示函数使用 `gt`。`setup` 中的导航、标签、选项和统计必须在 `computed` 或响应式 getter 中翻译，避免语言切换后仍保留旧值。
3. 保持 `{name}`、`{count}` 等参数不变。代码、文件名、API 枚举、选择项的 `value` 和权限判定不能使用译文。字面量花括号、`@`、`|` 要按 vue-i18n 语法转义。
4. 日期、数字、列表及排序使用当前 `locale` 或 `getLocale()`，不要固定 `zh-CN`/`en-US`。名称和文件内容保持原样，仅改变格式及排序规则。
5. 执行类型检查和国际化检查：

```bash
cd web/ui
npm run check
npx vitest run src/i18n src/api/hostErrorCopy.test.ts
```

`node scripts/i18n-catalog.mjs` 可将源消息导出为 JSON，供离线维护或翻译工具使用。覆盖检查应验证各语言键一致、参数完整、真实消息编译、英文无中文残留以及新增界面硬编码。

## Office 与运行边界

Office 配置在服务端根据 `Accept-Language` 选择编辑器语言，再签发 JWT。已打开的文档不会因切语言而被销毁重建；重新打开编辑器后采用新语言，以免丢失未保存内容。网页和 HTML 预览也不会因界面语言切换而重新导航或重放操作。

本次维护修改源码和测试，没有更新 Docker 或仓库中供 Go 嵌入的旧前端产物。发布时应重新构建前端和应用。
