## 逐标签接管（2026-10-08，已部署）

本机正式环境已更新为 [实时通道部署记录](browser-web-live.md#本机-docker-最新部署记录) 中的 `1e3cf69e3d67` 主服务与 `fff82d8cf752` worker，已通过真实网页、逐页控制、收藏界面、真实模型与工作流验收；其他服务器需独立部署。

当前以每张 Page 为控制单位：接管 A 只局部阻止并等待 A 的当前原子动作，不取消 B 上已执行的 Agent 动作，也不在 Go 中取消整轮模型。控制请求必须绑定 `context_ref + tab_id`，成功回执核对 `viewed_tab`；旧的无标签请求明确返回 400。顶层 `control/control_epoch` 属于观看页，`active_tab` 属于 Agent；`tabs[]` 公开每页的控制状态和代次，不公开租约。租约在同一窗口内按会话、context 和标签保存，人工输入不改变 Agent 的执行页，弹窗继承发起页归属。标签接管仅更新该页代次，context 取消/重建才更新 generation。

`tabs`、新建独立页和切换到 Agent 页不再因另一页被人工接管而全局拒绝。Agent 应先判断任务依赖：独立任务可使用 `{"action":"tab","tab_action":"new","url":"https://example.com/"}`；已有空闲 Agent 页用 `tab_action: "switch"` 与 `target` 选择。下方代码更新新增按任务显式 `claim` 当前人工页的能力；不能用新标签或 claim 绕过仍在进行的人工输入、登录挑战或取消保护。另开 Page 仍在同一 BrowserContext 中，共享同源 Cookie、存储与登录/退出影响，不构成独立账号隔离。

### 当前 Sheet 导航与自主接续（2026-10-10，代码更新）

此节描述源码契约，不表示已部署。普通阅读链接默认使用当前 Page/Sheet，明确新开意图和必要的登录/授权弹窗保留独立 Page。人工动作产生的 Page 保持人工控制；人工点击“＋”的 `/browser/tabs` 创建结果仅在已认证的同会话响应顶层返回该新 Page 的 `lease_token`，绑定校验要求 `context_ref`、`tab_id`、`state.viewed_tab` 一致，且 `control:human`、generation、control_epoch 有效。普通 state 和 tab rows 不公开租约。弹窗的公开 `opener_tab` 与 `inherited_control_epoch` 只用于客户端核对同一发起页的现有租约，不能授予新的控制权。

Agent 的 `tabs` 观察每行增加当前 `context_ref`，与已有 `id/control/control_epoch` 一起描述可选择页面。Agent 可自行判断是否接续任务相关的人工页，复制同一条新鲜观察的绑定后独立调用：

```json
{"action":"tab","tab_action":"claim","target":"t2","context_ref":"ctx_012345678901234567890123","control_epoch":3}
```

`claim` 明确转换并选择一张人工 Page，保留现有 URL、浏览历史、DOM 和登录态，不重建 Page、不访问新地址、不影响其他页。Go 工具只接受有效页签/context、安全整数控制代次，拒绝 URL、租约、force 及 batch claim；`switch` 和普通页面动作不能隐式接管。worker 重新核对 context、页签、控制代次以及当前输入/执行状态，并撤销旧人工输入权限。过期 claim 不重试，也不以读取当前状态后自动改写原请求代次的方式“补救”。用户再次接管后，旧 Agent 观察及动作继续失效。

成功 claim 的 UI 控制更新只采用该动作受保护的回执：所选页/context 必须吻合，`control:agent` 且控制代次恰好推进一次。普通工具结果、其他页回执、缺失/过期身份或事后另读到的状态不能清除人工租约。Agent 成功后重新观察；任务相关性由 Agent 结合用户目标与页签元数据判断，不批量抢回所有人工页，密码/MFA/验证码和权限弹窗仍由用户完成。

真实 viewport 保持桌面宽度至少 1280、高度至少 720 CSS 像素，最大 2560 × 1600；窄 Dock 缩放展示，宽沉浸视图才扩展网页布局。Agent 控制且空闲时，观看窗口可通过现有 WS 做仅显示用途的 resize；它不取得人工输入租约。忙碌、过期帧或结果未知时延后，不能在 Agent 依据旧截图操作时改变坐标。人工接管页的 WS 输入可与其他已知状态标签的 Agent 动作并行；HTTP 人工导航仍经过 Go 串行队列。任何未确认取消/输入结果继续封锁整个 context，单页接管不能清除该封锁。

本次完整 Go Web 包回归及 race、运行时 207 项、前端 3731 项、真实 Docker 网页 15 项和真实模型/工作流验收均通过。模型保留人工页 t1，在新页 t2 完成一次提交；沉浸后的真实文档尺寸由 1280×1600 更新为 2084×934。

## 执行方式

配置 `POGO_BROWSER_URL` 和 `POGO_BROWSER_TOKEN` 后，Web 会话使用独立的 Playwright/Chromium 服务，直接打开目标原始 URL。目标页面不经过 `/panels/`，不重写 HTML、CSS、JavaScript、Cookie 或 CSP。Pogo Web 经 WebSocket 显示 Chromium 连续 JPEG 帧，并通过专用输入消息操作同一个 Page；不通过跨域 iframe 读取目标 DOM。Agent 保留 DOM 与 CDP 工具链，不依赖截图识别来完成全部操作。

### 页面读取与连接状态

页面观察有总时限；同一 frame 的同类读取尚未结束时，不再向 renderer 累积相同读取。超时后的晚到结果不能写入后续操作的元素引用、结构证据或页面版本。`snapshot` / `find` / `extract` 等读取超时不会占住真实输入的 pending 状态。输入已经派发、但后续观察不完整时明确返回这一事实并停止 batch，不能自动重放输入；真实输入或调试执行结果未确认时仍保留 pending 保护。

面板先核对绑定 state，再申请短时单次票据连接实时通道。普通显示使用 WebSocket 推送的 state 和连续画面，不逐次轮询截图；断线会重新申请票据，不重播输入。画面、目标、控制代次或 viewport 不匹配时暂停人工操作，等待新连接或新帧。页面仍加载和连接失败分别呈现。

连续画面的人工输入坐标按已确认帧、顶层文档、viewport、租约和控制代次校验；普通 DOM 变化不会让正在进行的拖动自行失效。它不携带可供引用的 DOM 版本。Agent 截图和引用模式仍使用单次严格观察：页面变化时可返回没有 `X-Browser-Version` 的仅供查看 JPEG，不能据此执行 Agent 坐标点击或只读元素引用；页签或顶层文档在采样中变化时直接拒绝该次截图。

### 网页加载与首屏展示

网页区域未取得首帧时使用主题背景，不显示居中的等待文字。连接、首次取图和顶层网页导航的正常等待在工具栏提示；页面已经取得可显示内容时立即展示。`page_loading` 来自当前页签的顶层加载生命周期，独立于 Agent 的读取、截图和其他动作状态；普通 fetch、子 frame 自身加载和 Agent 忙碌不能直接当作顶层网页加载。确定的导航失败通过有限的 `page_load_error` 提示，响应不包含原始网站 URL 或底层请求诊断。

人工导航期间仍可观察状态和画面。连续帧消息带 `frame_identity`、`generation`、`control_epoch`、context、标签和 viewport；单次 `/frame` 观察另带 `X-Browser-Frame-Identity` 与可用时的 `X-Browser-Version`。同一页签导航时可保留已有画面供查看，输入先失效；切换页签或会话不能沿用其他页面的图。正常画面更新和只读提示收进工具栏，连接失败、断点和弹窗等明确异常仍有可读反馈。

正常 Web 画面使用同一 Page 的 CDP `Page.startScreencast`；客户端确认解码，服务端只保留最新待发送帧，避免追赶积压画面。Agent 截图和引用采样继续使用现有 `frame()` / `Page.captureScreenshot`，保留有界读取、单次在途和迟到结果隔离。两类观察不启动第二浏览器，也不重放网站请求。这是 WebSocket 连续 JPEG，尚非 WebRTC 或本机原生显示，性能需要在实际 Docker Web 链路测量。

原生服务是唯一浏览器执行器。未配置服务地址返回 unavailable；配置错误或服务故障明确报错，没有旧面板或网站反代执行回退。部署步骤见 [运行时 README](../browser-runtime/README.md)；开发和部署目录分别提供 `compose.browser.yml` 叠加配置，现有运行中的服务不会因源码修改自动更新。

Agent 链路：`browser 工具 → BrowserGate 任务授权 → Go 会话桥 → 私有鉴权 HTTP → Playwright/CDP → 原始网站`。人工链路：`Pogo Web → 会话票据与 WebSocket → 同一 Page 的 CDP Input.*`。两者使用相同的执行器、会话隔离和控制权边界。

## 本阶段能力

- 原始 http(s) URL 导航；DOM 文字、元素引用与定向查找；浏览器原生点击、填表、选项、按键、悬浮、滚动和条件等待；读取元素文本。
- 原生 `devtools(method, params, target?)` 对当前标签页所属目标执行标准 CDP；`targets.list` 发现页面、OOPIF 和 dedicated worker，再用 worker 签发的引用选择目标。网络、Console 和事件默认聚合本标签页所属目标，也可定向过滤。JavaScript 求值统一使用 `devtools` 的 `Runtime.evaluate`，旧 `eval` 动作已退役。范围、示例和测试记录见 [浏览器调试协议](browser-devtools.md)。
- 一个会话内多个标签，每张右侧浏览器 Sheet 绑定独立 Page；观看其他 Sheet 不改变 Agent 执行目标。新建后台空白页不取消 Agent。点击 × 关闭时，前端自动取得目标页的人工租约；已有本窗口租约则直接关闭，不自动强制抢占其他窗口。关闭成功后的迟到状态不会重新添加该页。
- `screenshot` 返回 viewport 图像；`click` 可在最近截图的 `version` 下使用 `x/y` 像素坐标。优先使用元素定位，导航或观察过期时重新获取状态。
- 图像保存在会话工作区的 `uploads/`，对话只保存引用。视觉模型在请求时读取像素；文本模型收到描述和图像路径，可在已配置视觉辅助模型时使用 `analyze_image`。
- 前端提供连续画面、原始地址、标签、文本提交、键盘、拖动和滚轮、原生弹窗处理、人工接管与交还。模型开始调用 browser 工具时展示浏览器面板。物理中文输入法和真实鼠标的 Web 手感验收仍需单独完成，不能沿用 Electron 的结果。
- 同一会话只由服务端执行 Agent 动作。操作 ID 在执行前认领，重复请求不重复执行；页面状态或导航变化后失效的引用不能继续使用。
- 人工接管使用窗口私有、按会话/context/标签绑定的内存租约；同页 Sheet 共享，其他页独立。接管只阻止并等待目标页的 Agent 动作，不暂停其他页或整轮模型；用户继续操作的是同一浏览器页面。另一窗口只能观察，显式重新接管会使旧租约失效；租约不存入 localStorage。
- 取消等待执行端确认后才放行下一轮。强制取消可能关闭正在执行的页面以中断浏览器调用，保留该上下文的 Cookie；已经提交到网站的业务动作无法撤回，未知结果不能自动重放。
- 每个 Pogo 会话独立 BrowserContext 和随机运行时标识；API 沿用会话归属鉴权。关闭/删除/空闲会话回收浏览器资源。没有 SSE 观察窗口也可执行已授权的 Agent 任务。

## 使用

启用服务后，在对话中输入 `/skill:browser-use 打开 https://目标网站 并完成任务`，或通过普通对话批准浏览器任务。需要登录时，在右侧面板点击接管，完成登录后交还控制，再明确让 Agent 继续。交还不会自动重放失败操作。

旧快捷方式和页签经过一次带备份的数据迁移，优先使用保存的原始地址；仅有 `/panels/名称/` 的条目通过独立迁移接口查询旧注册表，无法还原的保留为待修复。日常导航只接受原始网址，不注册代理或隐式解析旧快捷方式。见 [单一路径迁移](browser-native-only.md)。

模型调用示例：

```json
{"action":"navigate","url":"https://example.com/"}
{"action":"find","role":"button","name":"Search"}
{"action":"screenshot"}
{"action":"tabs"}
{"action":"tab","target":"t2"}
```

一次普通动作 batch 最多 12 步。执行过程中发生导航、标签切换、错误、取消或控制权变化时停止后续步骤，基于新观察继续。`devtools` 独立调用，不允许嵌入 batch。工具回执成功只表示动作完成，最终业务结果仍需核对。

模型收到的声明只包含当前原生能力；`api_read`、`auth_status`、`eval` 及旧面板执行链路已退役。未知或旧版执行器不能派发动作。每个 batch 子项都有完整字段类型与 `action` 枚举，整批参数在执行任何动作前校验。`type` 必须明确提供 `text`，空字符串表示清空；`select` 的选项放在 `text`，不猜测别名。

图像能力取决于完整调用链路：直接视觉模型获得像素；有 `analyze_image` 的文本模型先使用辅助工具；没有图像解析路径时使用页面文本和协议结果，不列出截图或坐标动作。模型切换会更新工具声明和 token 开销估计。子 Agent 通过私有 FD 同时继承后端标识与原生调试能力，但当前 CLI/FD 没有图像解析器；用户查看画面和评测截图归档不受此限制。后端元数据仅描述能力，不改变任务授权、人工控制或租约。

## 沉浸模式与操作提示

浏览器或文件预览页签的工具栏提供「沉浸模式」：网页铺满应用工作区，原有对话显示为右下角悬浮窗口。窗口可通过标题栏拖动、右下角调整大小，也可收起后从「展开对话」恢复。窄屏自动采用贴底布局。工具栏或对话标题栏均可退出，`Shift + Esc` 退出沉浸，`F6` 在原生浏览器画面与对话输入间切换焦点。等待用户确认时自动展开对话。

原生浏览器的主工具栏保持单行：刷新、原站地址、接管/交还和更多菜单。Agent 控制时地址可选中复制；人工接管后可在同一地址栏编辑并按 Enter 导航，中文输入法确认不会触发导航。页签统一通过外层 Sheet 的“＋ → 浏览器”和关闭按钮管理，内部不再保留第二套页签栏；「更多」收纳已有站点和操作说明。完成动作不常驻长状态句，执行中、失败和待处理弹窗在画面附近提示。刷新按钮核对状态与连接，引用模式另更新单次观察，不重载目标网站；更多菜单打开时，首次点击画布只收起菜单，不执行网站点击。

定向 state/frame 读取及 live 连接绑定同时携带 `tab_id` 和 `context_ref`。state 返回 `viewed_tab`，其地址、标题、加载状态、版本与画面均属于观看页；`active_tab` 仍是 Agent 执行页。实时输入带当前帧、generation、control_epoch、租约和严格递增序号，执行前再次核对；单次 JPEG 额外回传 `X-Browser-Context-Ref` 和 `X-Browser-Viewed-Tab`。上下文不匹配返回 409，目标已关闭返回 410；绑定请求不会静默恢复成其他页面。

### 新标签页与收藏栏

已连接的 `about:blank` 页面显示与当前主题一致的新标签页：收藏卡片、添加收藏和管理入口。工具栏下的收藏栏在已打开网页上也保持可见；未添加收藏时给出添加入口。空白页面继续接收绑定状态，以便 Agent 导航后显示网页，界面不把裸白色空白帧当作新标签页内容。网页加载、失败、断点或弹窗按各自状态显示，不能用新标签页掩盖。

已有人工控制权时，点击收藏在当前 Sheet 的真实 Page 导航。未接管时先选中收藏，再显式点击“接管并打开”。现在只接管当前页，不中断其他页上的 Agent；添加、编辑和导入收藏不需要接管。接管后的控制代次变化可以继续同一页面上的明确选择，但文档变化、关闭或切换 Sheet 会取消待打开项，迟到回复不能自动覆盖另一页面。刷新和恢复只呈现收藏，不自动访问保存的网站。

「选择网页元素」小手按钮开启只读选取：暂停更新展示画面，取得一次严格版本截图，悬停高亮元素，点击将元素摘要加入原有对话输入框，随后退出并恢复连续画面。网页本身仍会运行，文档变化会使观察失效；这不是冻结浏览器或新建执行器。已有草稿和其他元素标签保留，用户仍需主动发送；Escape 可取消。该模式不需要人工接管，不把悬停、点击、滚轮或键盘事件发送给网页。浏览器忙碌或有待处理弹窗时不可选取，画面过期时刷新后重新选择。

悬停通过鉴权 `/browser/pick/preview` 只取元素类型和矩形，不读取名称、正文或签发正式引用。前端按 50 ms 节流，同一时刻只保留一个实际请求和最新指针位置；离开当前矩形立即撤框，旧位置的迟到响应不能把框移回去。点击优先于尚未发出的悬停，重新预览点击坐标，再携带短期、单次使用的 `preview_token` 请求 `/browser/pick`，严格核对页签、画面版本、控制代次和同一个实际节点。

确认后的结果经过字段白名单沿现有 `ElementPick` 链路传入对话。`pN` 是当前文档中的只读观察标识，不是可执行的 `eN` 元素引用或 CSS selector，Agent 要操作该元素仍需重新观察定位。选取不清空 Agent 引用，不调用页面自定义取数函数，不读取表单值、密码或隐藏字段；页面摘要作为不可信引用材料处理。两个接口使用同一容器 Chromium、同一 Page 和同一选取器，不构成另一条浏览器执行路径。

普通跨域 iframe 和开放 Shadow DOM 可定位；复杂变换的 iframe 无法可靠换算时只返回 iframe 容器，封闭 Shadow DOM 和 canvas 内部对象不做解析。版本跟踪 DOM、滚动、尺寸、动画状态与可观察的资源加载变化，并非每个合成器像素的冻结证明。悬停通过增量观察新增子树、Shadow Root 和累积变化检查版本，截图与点击确认仍执行完整检查。运行中的布局/变换动画和超过只读扫描预算的页面会拒绝选取，普通画面仍可查看。

预览和确认共享按页单次在途保护，响应时限分别为 750 ms 和 1500 ms。超时不会假定底层 Chromium 读取已经取消：服务返回 `PICK_OBSERVATION_PENDING`，界面停止发出选取请求，直到新读取的绑定状态明确返回 `pick_pending: false`。恢复后只重新预览，不重放此前的点击确认。

模式切换只改变现有组件的布局，不重新挂载浏览器、不新建会话；草稿、附件、对话流与当前窗口的人工接管租约继续使用。普通布局的侧栏、分栏比例和上下排列偏好保留。系统全屏是独立按钮，浏览器拒绝或不支持时仍可使用窗口内的沉浸模式；它需要用户主动点击，遵循 [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) 的要求。悬浮对话不锁住网页的键盘焦点，保留明确的焦点切换和退出入口，遵循 [WAI 的无键盘陷阱原则](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap.html)。

操作状态由执行端提供。普通连续帧没有严格 DOM 观察版本，不沿用旧截图中的目标矩形、指针或焦点标记；单次观察只有版本和页签匹配时才可显示相应空间提示。提示画在 Pogo 层，不向网站插入可见元素，也不为了播放动画额外移动鼠标。`fill()` 聚焦输入控件不代表鼠标经过该控件，不把元素中心伪装成实际点击点，反馈标签不包含输入值或密码。

这仍是容器网页的远程可视化。连续传输改善原先逐动作截图和输入观察的等待，但 JPEG 编码、带宽和显示延迟仍需测量；不能声称已经达到 Codex 本地原生显示的性能。

## 当前边界

- 主路线是 Docker 中的托管浏览器。没有实现接管用户本机 Chrome 的扩展，也不会自动继承本机登录态；Electron 是独立可选实验。
- 登录态在当前浏览器上下文内复用；关闭会话、空闲回收或 worker 重启后可能需要重新登录。尚未实现跨 worker 重启的账号 profile 持久化。
- 正常画面为 WebSocket 连续 JPEG，尚不是 WebRTC 或完整远程桌面。文件上传/下载交接、远端选择复制到本机剪贴板、硬件认证和浏览器系统权限窗需要后续专门支持。Web 物理输入法与手感不能从合成事件测试推定通过。
- 标准 CDP 绑定当前标签页及已验证归属的子目标，拒绝跨标签/会话、浏览器级及任意 target/context 路由、主机文件与直接凭据管理等方法。脚本求值不是只读沙箱；它们与普通动作共用任务授权、人工租约、代次和取消控制。
- 当前是 Agent 调试协议与有界记录，尚未嵌入完整 Chrome DevTools frontend，未暴露公共浏览器级 WebSocket。已递归附加 OOPIF 和 dedicated worker；shared/service worker、未成功附加的目标、附加前历史和完整 trace/heap 导出仍未覆盖。目标发现会明确报告初始化与容量拒绝，不承诺全浏览器完整追踪。
- BrowserContext 隔离 Cookie 等浏览状态，不是独立的操作系统租户边界。worker 独立于 Pogo 服务运行，不挂载 Agent 工作目录；Chromium 沙箱保持启用，服务端口不对公网开放。生产网络出口和并发资源需按实际部署配置。
- 自动化挑战、验证码和设备绑定登录仍可能需要人工操作；没有以原生浏览器运行作为规避网站限制的承诺。

## 异步动作观察（2026-10-01）

- agent 的 click、type、select、press、hover、scroll、navigate 执行后，worker 等待本次动作发起的文档加载完成、fetch/XHR 收到响应，再留静默窗口（最终观察 150 ms，batch 中间步骤 40 ms），然后取观察。上限由 `POGO_BROWSER_SETTLE_MS` 控制：默认 2000 ms，最大 5000 ms，且不超过动作超时的一半；`0` 关闭。只统计 document/fetch/xhr，图片、字体、媒体和长连接不阻塞观察；导航遗留、iframe 卸载和页面关闭的请求立即不再计入。读取类动作、显式 wait、切换标签和人工输入不等待。
- 回执新增 `settle_ms`；到上限仍未完成时有 `pending_requests`；动作打开新标签时有 `opened_tabs` 与 `from_tab`，新标签成为活动标签，回执观察的就是它。Go 工具把后两种情况写成明确提示，并要求用带条件的 wait 等结果、不要重复动作。
- 等待只观察、不重放；对话框、取消和接管会立即结束等待，整体仍在动作超时预算内。
- worker 端 type/select 必须给字符串 `text`（`""` 清空 type）。Go 在审批和执行前对缺 action、batch 子项缺 action、wait 缺条件给出定向修正提示。

## 等待范围与观察准确性（2026-10-02，源码改动）

本轮在工作区继续修复，未替换前述线上镜像。

- 等待范围收窄到动作起始页面（含其 iframe），以及由 Playwright opener 事件确认的新增后代弹窗。已有后台标签的请求不再占用等待预算，其弹窗也不抢走本次动作的观察页面。同一页面的定时器请求仍可能计入，因此回执只描述“期间观察到的相关页面请求”，不把时间先后当作因果。
- `settle_ms` 包含新页额外的 DOM 加载等待；轮询末尾按剩余预算休眠。两份 Compose 都透传 `POGO_BROWSER_SETTLE_MS`，默认 2000，显式 0 关闭；改 env 文件后仍需重建对应 worker 容器才会生效。
- `from_tab` 仅记录动作来源，不再声称原页面没有变化或必然仍可返回。普通成功回执不增加额外观察要求。
- 来源页面打开新标签后立即关闭时，Playwright 可能不提供 popup 归属事件。无法确认结果页时，回执明确说明观察未确认并列出可用标签，停止 batch 后续步骤；模型可以通过 `tabs` 和显式 `tab` 恢复。不会把旧首页当成业务结果，不猜归属、不重放动作。
- fetch/XHR 仍在收到响应头时结束追踪，以免未消费正文的请求长期挂起。慢正文或延迟 DOM 更新可能晚于等待结束；没有 `pending_requests` 不代表业务完成，必须用明确条件等待和实际回执确认。新增回归覆盖这些边界及实际业务写入仅一次。
- Linux 验证暴露了原有的鼠标事件归因问题：Chromium 初始化时的可信移动事件被错误归给 navigate。现在只有 click/hover 可认领新的指针事件，并绑定动作起始页签、文档与 generation；坐标点击使用相同约束。导航、填写和键盘动作不制造鼠标移动，仍保留有效的历史指针。原有代码在相同 Linux 条件下也复现，未通过删除断言放行。
- 本轮完整 worker 测试在 macOS 和 Linux/arm64 各 40/40 通过。Linux 使用原 worker 镜像的依赖、只读挂载候选 src/test，在无外网、非 root、只读根、capabilities 全移除、seccomp 和 Chromium sandbox 启用的临时容器中运行；不是替换生产容器，也不等于已经构建候选发布镜像。Compose 配置解析 4 项测试（10 个组合）及原部署 mock 16 项通过，确认默认值、自定义值与显式 0 的传递。
