# ChatGPT 引用对标与 Pogo 改进

调研日期：2026-10-09。范围：回答中的网页/文件引用、证据预览、来源汇总、引用漏标。

## 依据与边界

本报告结合用户提供的 ChatGPT 引用截图、OpenAI 官方文档及 Pogo 当前代码。官方 API 的公开设计可以用来指导 Pogo，但不能据此推断 ChatGPT 未公开的模型提示词、校验算法或所有账户版本的界面。此次访问 ChatGPT 公开首页处于未登录状态，没有取得账户内动态引用交互的对照录像。

| 官方公开事实 | 对 Pogo 的启示 |
| --- | --- |
| 引用系统需要明确可引用单元、来源内容、标记格式、提示和解析；来源标识与展示定位应区分。 | 继续使用现有稳定来源 ID；文件行范围只取已记录的读取位置，不能由页面样式或模型自由编造。 |
| 引用应靠近所支持的句子/段落，不能全部放到回答末尾。 | 正文引用保留为主要验证入口。底部按钮不替代它。 |
| Web Search 返回正文引用及 URL/title/location 等元数据，要求界面中的正文引用清晰、可点击。 | 短站点标签负责阅读，完整标题、位置与原文在详情中展示。 |
| Web Search 的完整 sources 与正文引用不同，前者可以多于后者。 | 区分“本回答实际引用”和“其他查阅材料”；不能将全部工具回执数量描述成实际引用数量。 |
| File Search 输出文件引用 annotations，检索结果需要单独请求。 | 来源列表、原文片段和回答中的定位是相互关联但不同的数据，不能用一个总列表代替。 |

上述依据分别见 [Citation Formatting](https://developers.openai.com/api/docs/guides/citation-formatting)、[Web Search](https://developers.openai.com/api/docs/guides/tools-web-search)、[File Search](https://developers.openai.com/api/docs/guides/tools-file-search)。

## Pogo 现状

现有链路已经具备来源注册、正文标记、悬浮卡、文件行定位与来源总览，不需要另建一套引用系统。最近一次记录排查发现，同一轮已有 11 条带来源的工具结果，但最终回答没有正文引用；同一会话更早的回答仍带引用。当前验证器主要拒绝不存在的引用 ID，无法发现“完全没写引用”。因此，“底部有来源”并不能证明正文引用生成成功。

引用图标补全和浏览器布局修复没有将正文引用搬到底部。浏览器执行、元素引用与回答证据展示也是不同层次，本轮主要改进 agent 回答质量及共享引用 UI。

## 本轮采用的方案

### 1. 正文、预览、总览共同工作

- 网页正文引用显示真实站点 host，保留内网端口和不同子域；完整文章标题在详情中显示，不从网页标题猜测“官方”品牌。
- 文件继续显示文件名与已记录的行范围；重复点击定位、键盘打开证据和历史引用保持可用。
- 相邻多个引用仍以短标签加 `+N` 合并，不把它们移出所支持的段落。
- 来源入口优先计数实际被正文引用的材料，其他查阅材料另行折叠。零正文引用时使用“查阅材料”，说明尚未与具体结论关联。
- 仅能确认是空操作回执、且未被正文引用的记录留在工作日志。点击后也可能返回真实页面文本，因此不能按操作名称直接剔除来源；不确定的历史记录继续保留。
- 空标签页初始化产生的 `about:blank` 和没有网页地址的 `tool://browser/…` 工具状态不进入默认材料概览；这项规则也覆盖没有新元数据的历史记录。根据来源类型、地址及空回执结构判断，不能仅按“Browser”标题过滤真实网站。被正文明确引用的诊断记录继续可追溯。
- 实际候选画面发现，浏览器回执前置的 DOM 证据 JSON 会抢先命中关键词。网页悬浮预览应从已确认回执中后附的连续原始页文取摘录；无法可靠识别时明确显示为工具输出，不递归抽取任意 JSON 字段，也不拼接不同 iframe 的材料。

### 2. 只对有依据却完全漏标的回答做一次补正

当本次任务确实成功取得了可引用材料，而实质性最终正文没有引用时，允许模型基于已有结果重新审阅一次。浏览器的打开或点击结果也可能带回完整页文，因此以实际成功返回的正文判断，不能仅按动作名称排除。单句打开确认、普通问候、纯状态、失败或空结果、只有历史材料的无关新请求不应因此被迫增加引用；合法 JSON 等机器输出保持原格式。

补正只生成文字，不执行工具。网络错误、空答案、协议异常或模型仍试图调用工具时保留原完整回答。它与既有错误引用修正共用有界预算，避免变成重跑任务或无限重写。模型必须只为已有材料实际支持的结论引用；没有支持时说明局限，不能为了通过检查补假引用。

这只是遗漏防护，不能保证每一句话都被材料支持。来源 ID 存在、引用可点击与事实核实是三个不同条件。补正也可能产生完整的无直接证据说明，不能仅因为它仍无引用就丢弃；这种回答仍显示“查阅材料”，不会被界面包装成已经引用或核验。纯“已补充引用”等补正确认不能代替原完整答案。

### 3. 保持格式与历史兼容

保留现有 `[1](#cite:S3)` 协议，不因 OpenAI 公开了自己的标记样式就迁移全部历史数据。Pogo 使用多种模型，直接照搬某一模型家族的特殊字符也不自动提高可靠性。

前端与后端统一合法 S 标签的大小写处理；不修改 URL、文件位置、代码示例或普通链接。错误闭合的 Markdown 不应被当作界面可显示的有效引用。原文与来源身份继续独立保存，显示标签变化不改变证据内容。

## 验证标准

1. 自然提问读取两份隔离材料，真实模型回答包含与结论就近的引用；不得在测试问题里强制给出标记格式来掩盖产品缺陷。
2. 可控模型回归覆盖零引用补正、历史隔离、中文短确认、错误/空结果、无剩余预算、补正失败和违规工具请求。
3. 正文、来源计数、悬浮卡及刷新后的引用身份一致；浅色、深色和窄屏可阅读，文件行范围与键盘访问不回退。
4. 分享、复制及历史来源不因标签缩短或大小写容错改变来源身份。
5. Docker 继续应用容器单独更新，浏览器 worker 保持原镜像与容器；维护期间验证、备份和原会话保留沿用既有发布机制。
