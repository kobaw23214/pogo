# 在聊天中指定 MCP 方法

输入 `/mcp:` 打开方法选择，支持按服务名、方法名和描述搜索。选中后可继续填写任务，例如：

```text
/mcp:gitlab/search_projects 查找名称包含 pogo 的项目，列出前五个。
```

选择只填入引用，不会立即调用方法。发送后，Agent 根据任务理解和工具参数定义调用该方法；缺少必填信息时应向用户确认。现有工具权限和审批规则继续生效。

方法可以作为顶部引用或正文内联引用，与 Skill、文件、网页元素、Office 和资料引用混排。不同服务的同名方法有独立身份。方法名称包含斜杠或特殊字符时，补全自动进行 URI 编码；结构化引用始终保存原始服务和方法名称。

目录只显示当前会话实际可用的方法，包含尚需通过 `mcp_describe` 获取参数定义的方法。首次发送之前使用当前 Agent 的已启用配置读取目录，不创建空会话。打开方法选择时会刷新缓存目录。忙碌会话使用已有的能力快照，配置在现有同步边界生效。

目录不可用或方法撤销时，已选引用和正文保持可编辑，发送前会提示原因。历史、复制、编辑、草稿和保存资料保留方法身份，不展示内部工具选择指导。冻结资料中的普通文字、网页内容和文件内容不会被扫描成命令；只有明确的结构化引用或顶层手写 `/mcp:` 前缀会被解析。

实现：消息部分为 `{ "type": "mcp", "server": "gitlab", "name": "search_projects" }`。历史文本块通过 `input_mcp: {server, name}` 保存本地显示元数据，模型侧只接收服务端生成的工具选择指导。`GET /api/tools` 的 `mcp_methods` 是精确可引用方法目录；`session_id` 指定会话范围，首条消息草稿使用 `agent_id`。
