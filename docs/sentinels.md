# 通用脚本哨兵

哨兵保存一份长期委托，托管 Agent 编写的观察脚本，并在脚本报告有意义的事件时唤醒 Agent。运行时不按 HTTP、RSS、文件、数据库等场景分类；来源协议、变化判断和业务条件由脚本实现。接入某个来源所需的程序、可读数据和网络权限仍须实际存在。

模型不需要在没有事件时持续推理。长期存在的是订阅配置、采集进度、事件队列和会话记录；关闭聊天页面不会等于删除哨兵。

## 运行方式

- `poll`：Pogo 到点启动一次脚本，传入上次提交的状态与游标。脚本返回一个结果并正常退出。空事件列表只更新采集状态，不触发模型。
- `stream`：Pogo 托管持续运行的脚本。脚本可阻塞在任何已授权来源上，逐行报告事件。进程异常退出时由运行时记录故障、退避和恢复；事件不应混在日志中。

两种方式共用持久事件队列和 Agent 唤醒机制。脚本不必自己实现模型 API、消息队列、轮询调度或聊天保活。

## Agent 工具

### `background_task`：创建后交还对话

模型可以通过同一个入口创建、查看、暂停、恢复或删除当前账号与 Agent 的后台任务。
固定时间或周期执行使用 `source=schedule`，按现有定时队列处理；脚本观察来源并按条件产生事件使用
`source=sentinel`，复用下述哨兵运行器。该工具是单独可选权限，选择 `watch` 不会自动增加定时任务管理授权。

例如“每两分钟执行一次，十分钟后停止”保存为间隔 120 秒及宿主计算的绝对截止时间：

```json
{"action":"create","source":"schedule","title":"测试目录统计","task":"统计当前工作区测试目录的文件数量，返回本次结果。","kind":"every","every_seconds":120,"timezone":"Asia/Shanghai","stop_after_seconds":600,"enabled":true}
```

`task` 描述每次触发要完成的一次工作，周期与寿命由宿主字段控制。首轮在登记后一个完整间隔执行；
到期时刻本身不再新启动，因此这个例子通常在 120、240、360、480 秒触发，并不隐含立即执行一次。
`expires_at` 和 `stop_after_seconds` 二选一，最终均保存绝对时间。重启、暂停再恢复和排队不能重置期限。
启动仍需用户授权；没有明确授权时创建为暂停状态。

返回 `background_handoff.registered=true` 只证明登记成功。Agent 应汇报任务编号、是否启用、下一次执行
和到期时间，随后结束当前创建委托，或继续用户另行要求的前台工作。不应使用前台 sleep、反复查状态
或 Todo“等待十分钟”来覆盖整个后台周期；也不能把登记成功说成未来执行与业务目标已经完成。
这项说明随实际任务工具视图发送，没有任务工具的会话不会增加相关提示。

期限控制后续工作接纳；已发生的外部操作不会回滚，已保存结果不会删除。普通定时任务已经开始的一次
执行仍有自己的取消与超时控制。哨兵到期会停止采集和新的模型唤醒，取消正在运行的采集/唤醒，并保留
已提交状态、结果和需要核查的中断批次。旧的无期限定义保持原样，不会从对话文字猜测并自动迁移期限。

### `watch`

支持 `prepare/create/list/status/pause/resume/retry/remove`。

Python 脚本优先使用通用协议辅助库。先准备一个独立目录：

```json
{"action":"prepare","script_path":"watchers/custom/main.py","mode":"stream"}
```

准备操作把版本化的 `pogo_watch.py` 和带未实现保护的入口放在同一目录。已有业务入口不覆盖；已有辅助库只有字节一致时才复用，不一致则拒绝并保留原文件。准备不会注册、执行、启用或授予网络权限，仍按写入动作审核。新的封存会核对辅助库内容并记录版本，已有封存版本继续按自己的清单校验。

业务脚本只实现来源连接、认证、条件判断和来源游标。例如下列来源函数由 Agent 按实际协议实现；辅助库本身不包含 HTTP、RSS、文件或数据库适配器：

```python
from pogo_watch import Watcher, event

with Watcher(mode="stream") as watcher:
    source = connect_authorized_source(watcher.cursor)
    watcher.checkpoint()  # 连接准备好后，验证协议就绪；不代表业务事实已核验
    for observation in source:
        cursor = source_cursor(observation)
        if matches_business_condition(observation):
            watcher.emit([
                event(source_event_key(observation), summarize(observation), observation)
            ], cursor=cursor)
        else:
            watcher.checkpoint(cursor=cursor)
    raise EOFError("source stream ended")
```

`Watcher` 读取 host boot，计算内容稳定的帧编号，限制 JSON 大小，并在 stream 的匹配 ACK 后更新 `state/cursor` 快照。读取快照得到深拷贝，修改后须显式传给 `emit` 或 `checkpoint`；省略表示继承，传 `None` 表示 JSON null。协议错误或 ACK 失败后不能继续提交。来源异常可退出，由原有监管器退避重启并传入最后确认的游标，通常无需另写确认或重连框架。

恢复了来源游标就应继续处理，不要重新初始化“首条历史基线”，也不能仅因某条数据是重连后的第一条便静默丢弃。判断重复必须依据来源标识、版本和游标含义；若来源保证只返回游标之后的数据，这些数据应照常经过业务条件判断。

`poll` 仍是一次读取、最后调用一次 `emit` 或 `checkpoint`、正常退出；不需要循环或休眠。其提交要等进程成功退出后才由 host 接纳，SDK 不把本地输出声称为已持久提交。

来源事件键由脚本选择，host 做持久去重；无需保留无限增长的已见列表。辅助库只减少协议样板，不是新的安全边界。Python、其他语言原有脚本仍使用同一个 v1 协议、封存和执行路径，原有沙箱与审批规则不变。

同一事件键的 `summary/data` 必须保持不变。路径消失、复制或改名不能成为复用同一键却改写载荷的理由；若需要记住来源身份，必须使用可恢复且容量明确的进度，不能靠丢掉旧身份让状态继续装得下。

### SDK 2 的容量与观察失败

新目录的 `prepare` 提供 SDK 2，线协议仍是 v1。旧封存和原目录文件不会自动覆盖，已确认的 `state/cursor` 也不会自动迁移或清空。采用新接口时，在新目录准备、保留原来源状态合同并重新测试，再显式替换注册；替换注册不等于去重历史已经迁移。

- `watcher.fail("capacity_exceeded")`：输入或所需身份历史不能装进其声明的容量。
- `watcher.fail("incomplete_observation")`：必要的观察被截断或未完整取得。
- `watcher.fail("source_unavailable")`：无法读取来源，不能据此声称没有变化。
- `watcher.fail("history_invalid")`：保存的身份历史损坏或版本不兼容，不能建立空基线代替它。

这些调用使用固定退出码，宿主显示“脚本报告”的安全失败类别，不转发可能包含来源秘密的 stderr。失败后的客户端不能再成功提交检查点；失败 poll 的提案不被接纳，stream 之前已经 ACK 的进度仍保留。它们不提高执行权限，也不改变原有退避策略。

SDK 能确认的状态、游标、帧、事件数量及内容尺寸超限也会抛出 `CapacityError`，固定退出 80；普通 JSON 格式问题仍为 `ValidationError`。容量失败不是可以捕获后再提交空结果的普通异常：在 `with Watcher` 内，即使捕获 `BaseException`，客户端仍保持失败。独立构造 `event()` 超限且未被捕获时同样退出 80。

`history = watcher.history(saved_history, max_entries=128, max_bytes=12288)` 可管理有限的来源身份，使用 `seen(key)`、`remember(key)` 和 `snapshot()`。它不会自动逐出旧键；满了或历史格式不兼容时明确失败。字节数按宿主相同的 JSON 转义方式计算，完整的外层状态仍须符合 16 KiB 限制。`snapshot()` 是待提交状态，必须随 `emit/checkpoint` 提交，不能当作持久确认。

仅在确实没有历史时传 `None`；恢复时传原先保存的完整历史值。不要以缺失字段、错误版本或解析失败为由传入 `None` 重置历史。该有限容器不提供永久、无限规模的去重；需求超过容量时，应采用可靠的来源游标或明确声明不支持，不能静默遗忘。

仍在写入中的记录可以保持显式 pending，等后续 poll 重试。不要把它标为完成、忽略或已消费，也不要将消费游标推进过去。相比之下，已经截断、超限或不可读的数据不能被当作成功的空观察。SDK 无法检查任意业务脚本主动忽略输入或自己输出成功帧；业务脚本仍须实际采用这些接口和合同。

先将脚本入口及其依赖放入独立子目录，例如 `watchers/custom/main.py`。Python、shell 和可执行文件可作为入口；其他语言可通过启动脚本使用已经安装的运行时。

创建时指定标题、长期任务、模式、脚本的工作区相对路径、字面参数和执行限制。owner、Agent、工作区、存储位置和唤醒批次由 host 绑定，不能通过参数或脚本输出修改。

```json
{
  "action": "create",
  "title": "业务变化观察",
  "task": "检查新变化，调查值得关注的事件，保存结果；没有变化保持安静。",
  "mode": "poll",
  "script_path": "watchers/observe.py",
  "args": ["--profile", "custom"],
  "interval_seconds": 120,
  "timeout_seconds": 30,
  "max_turns": 20,
  "enabled": false
}
```

脚本注册时保存不可变副本。修改工作区里的原脚本不会悄悄改变已注册哨兵的执行内容。

创建默认暂停。`resume` 开启采集和未来自动运行，授权含义包括聊天结束后继续观察。`pause` 停止后续采集/派发；它不能宣称已经回滚任何外部操作。`status` 用来分别检查配置是否启用、来源是否运行、最近故障、积压事件和处理结果。

`retry` 是对中断工作的显式恢复请求。它可能继续或重新执行之前未完成的工作，应先核查状态与可能已经产生的影响。普通 `resume` 不会自动重放中断的 Agent 工作，进程重启也不能据此盲目重做外部动作。

### `watch_test`

可以使用当前 Agent 的已保存 `watch_id`，也可以试跑未注册脚本：

```json
{"script_path":"watchers/observe.py","mode":"poll","timeout_seconds":10}
```

试跑最多 30 秒，使用隔离的测试状态，展示协议输出和错误，不推进正式游标，不开启正式监听，不唤醒 Agent。测试已保存哨兵时不能同时覆盖脚本、参数、模式或网络权限。

试跑成功证明短时间内脚本与协议能工作，不代表来源在断线、重启、压力或长时间运行后都可靠。

返回值明确标注验证范围：业务条件未被自动核验，stream 的完整 ACK 循环也未由这次首帧试跑证明。不能把这些标记为 false 的检查写成已经独立验证。

持续流没有值得报告的变化时，可以在启动或游标变化后输出 `events: []` 的检查点并等待确认。它只提交采集进度，不唤醒模型。试跑在首个有效帧后结束，不能据此声称整个确认循环已验证。测试窗口内没有帧会明确返回“协议尚未验证”，不能把来源安静或超时当作验证成功。

### `watch_decide`

只处理当前运行所绑定的事件批次，不能指定任意 Agent、哨兵或批次。

```json
{"decision":"report","summary":"调查完成，以下是本次结果。"}
```

- `ignore`：已核查且无需后续处理。
- `report`：调查完成，保存结果。保存 Pogo 报告不等于向外部发送消息。
- `defer`：保留待处理工作，并指定 `defer_seconds`；它不是完成确认。

`investigate` 不是终态。需要调查时在当前有界运行内完成，再提交有效决定。工具提交的是处理决定；最终结算还必须符合运行完成及持久化条件，不能只靠模型文本声称成功。

每次唤醒都会带报告依据约定：区分观察时事实、依据明确规则的推断和未知内容。统计为 0 不能自动推成整体安全或低风险；缺少字段不能默认为 0，异构结构也不自动等于损坏。长期目标给出或授权调查核实了适用规则时，可以据规则判断，并说明证据范围。

结构化观察已足够完成目标时，直接核对并报告，不为重复验证同一事实额外执行命令或重读来源。确实需要新调查时仍遵守原审批。`watch_decide.summary` 是持久报告本体，不能先保存无依据判断，再靠最后一条聊天回复修正。宿主若因输入上限省略观察明细，会明确告知；未附上的明细不能被声称已经完整核验。

## 生成中断与有限补全

Manager 管理的 Web 工具会话在模型返回 `max_tokens` 时，最多触发一次自动补全，沿用同一次运行的轮次、时间和费用等已有约束，不提高模型配置中的输出上限，也不开始一个新运行来重置预算。截断的工具参数不会执行，先保存对应拒绝结果后再补全；已经完成的工具结果留在历史中，不由宿主自动重放。

再次截断或没有剩余预算时明确停止，页面说明本次处理未确认完成，可以发送“继续”接着处理。连接超时、鉴权错误和用户取消不走这次自动补全。连接中断可能缺少完整用量回执，页面保留中断原因，由用户决定是否继续。该策略不自动扩展到 CLI、Workflow 的独立执行器或外部嵌入者；嵌入者须显式设置 `agent.Config.Continuation`。

最近一次运行的终止原因随存活会话的 Hub 快照发送，页面重连或刷新后仍能显示未完成提示；新运行开始、正常结束或回退历史后清除。这里不是新增服务重启后的终止状态持久化承诺。

## Pogo v1 脚本协议

这是 Pogo 的版本化协议，不是所有 Agent 产品共享的标准。

标准输入第一行是 host 提供的 boot：

```json
{"v":1,"kind":"boot","mode":"poll","workspace":"/authorized/workspace","state":null,"cursor":null}
```

脚本从 `workspace` 读取经过授权的数据。工作目录是封存后的脚本目录；不要假设它等于整个 Agent 工作区。

标准输出仅写 UTF-8 单行 JSON：

```json
{
  "v": 1,
  "id": "stable-frame-id",
  "events": [
    {"key":"source-item-42:version-3","summary":"发现一项值得调查的变化","data":{"item":"42","version":3}}
  ],
  "cursor": {"last_id":"42"},
  "state": {"last_version":3}
}
```

实际输出时把整个对象编码在一行。`events: []` 表示静默检查。`id` 标识一次可重放的协议帧；`events[].key` 标识来源中的逻辑事件或内容版本。重启后重放同一事件时，事件键必须稳定，不能每次重新生成 UUID。

- 单帧最多 64 KiB；状态有独立大小限制。
- `data` 是来源数据，不是系统指令或新的权限。
- 日志只写 stderr，保持有界。不要把密钥或令牌输出到日志/事件。
- `poll` 必须恰好输出一个完整帧并以状态码 0 退出；失败退出不提交它提出的状态。
- `stream` 每输出一个完整帧，由运行时事务保存事件、游标与状态后，才从 stdin 返回确认：

```json
{"v":1,"kind":"accepted","id":"stable-frame-id"}
```

确认表示可靠接收，不代表 Agent 已处理或报告已送达。脚本在确认前应保留重发能力；单纯 flush、exit 0 或关闭管道都不是业务处理确认。

## 最小可运行 poll 示例

这个示例只在首次观察时发出一个测试事件。替换观察逻辑即可使用任意允许的来源；无需更改运行时。

```python
#!/usr/bin/env python3
import json
import sys

boot = json.loads(sys.stdin.readline())
state = boot.get("state") or {}
events = []
if not state.get("emitted"):
    events = [{"key": "demo:first-observation", "summary": "首次观察完成"}]
print(json.dumps({
    "v": 1,
    "id": "demo:first" if events else "demo:quiet",
    "events": events,
    "state": {"emitted": True},
    "cursor": {"version": 1}
}, ensure_ascii=False), flush=True)
```

如果正式脚本在不同采集进度输出不同帧，必须选择不同帧 ID。相同帧 ID 携带不同内容会被视为冲突。

帧 ID 与事件键承担不同职责：同一个来源观察首次产生事件、下一轮变成空事件检查时，完整帧的内容已经变化，必须使用不同帧 ID；来源事件键保持稳定。可以对 `events/state/cursor` 的规范化 JSON 计算摘要作为帧 ID，摘要不包含帧 ID 自身。重放完全相同的帧才复用原帧 ID。冲突诊断会分别指出帧 ID 或事件键的问题，拒绝的帧不会覆盖已经保存的状态。

## 权限和恢复边界

脚本默认断网、读取受限目录，环境中不继承模型 API key 或主服务凭证。`network=true` 是显式权限请求，host 决定是否可授予；它不表示已经实现网站级白名单。采集和被唤醒 Agent 的动作权限是不同边界，脚本不能通过输出申请自动批准。

采集 cursor 表示来源记录已落入 Pogo，处理状态表示 Agent 已作出有效决定。两者分别持久保存。繁忙时事件仍然排队，正在执行的批次内容固定，新事件进入后续批次。

来源没有可重放日志、游标或补扫能力时，Pogo 无法重建来源未交付的所有中间变化。脚本应在启动、恢复或来源溢出后重新核对权威状态；“没有新事件”不能代替来源健康检查。

临时采集失败按 2、4、8 秒等间隔退避，最长约 256 秒；已持久安排的重试到期后继续尝试，不会因为连续失败五次便永久停止。重启服务会保留未来的重试时间，不会提前启动。失效或被篡改的封存脚本没有自动重试计划，仍须检查版本并显式恢复，不能通过临时故障重试绕过校验。

来源游标是来源定义的数据，SDK 不判断其是否过期，也不会静默清空游标或重建基线。来源拒绝旧游标时，业务脚本须按该来源的可靠规则补扫、对账或明确失败；来源已经删除且无法补回的数据不能被声称为已恢复。

默认公共错误只返回失败类别、退出状态与 stderr 字节数，不拼接脚本的原始 stderr；畸形 JSON 也不回显未知字段名，冲突身份只显示稳定摘要指纹。这些保护不会修改参与去重、提交和 ACK 的原始载荷。显式的诊断回调仍接收不可信日志，调用者须自行保护。

这不是通用秘密保险箱：同一 Agent 的状态查询和试跑可以看到原始参数、state/cursor，事件内容会交给被唤醒的模型；普通 Bash 自测也有自己的日志通道。不要将密码、认证头或来源令牌放入这些展示数据、事件标识、日志或异常。平台不能可靠识别任意脚本主动输出的所有秘密。

已开始但没有最终回执的运行要显示中断/待核查。写文件、提交页面、发送消息等外部动作若可能已经生效，恢复前须进行业务对账或使用目标接口的幂等键。重复事件去重不等于所有外部操作都能 exactly-once。


## 首期运行预算

- 最多同时执行 4 个采集脚本，其中持续流最多 3 个，为短检查保留槽位；其余显示等待容量。
- 最多同时唤醒 2 个 Agent；每个哨兵串行处理批次，默认每次最多 32 轮、最长 10 分钟。自动压缩也受本次准备阶段时限约束，并先保存持久准备回执。
- 每个哨兵最多积压 1024 个事件；每批最多 32 个事件及约 64 KiB 输入。达到上限时拒绝确认，保留原采集游标。
- 每个哨兵使用保守的约 100 次/日唤醒准入限制；延期/重试可能保守多计，不是精确计费统计。`status` 独立展示准入是否被预算阻挡。
- 事件数据库及 WAL 合计达到 256 MiB 后暂停接纳新观察，不会静默丢弃已确认事件。首期保留去重历史，没有自动清理策略。
- 脚本默认采用采样监督（256 MiB、64 个进程/线程、约 0.25 核）及有界临时空间。它不是每个哨兵独立的 cgroup 硬隔离，容器仍提供共同硬上限。
- 被唤醒的工作会话默认严格审批；当前版本未把交互式工具审批改成可跨重启的长期审批单。

本功能是通用脚本运行与交付机制。它不保证未安装的协议客户端、尚未授权的资源或任意外部系统天然可访问，也不把注册成功等同于真实业务验收通过。

## 真实模型验收

`web/sentinel_live_test.go` 包含显式启用的真实模型验收。它使用独立的 Manager、Agent、会话和数据目录，调用配置中已有模型；不会修改模型配置或访问现有业务会话。默认测试会跳过这些用例。

在具备 Python、bubblewrap 及对应沙箱权限的隔离 Linux 环境中，设置 `POGO_SENTINEL_LIVE=1`、`POGO_CONFIG` 和模型所需的凭据环境变量，再执行：

```sh
go test ./web -run '^TestSentinelLive(Poll|Stream|Composite)$' -v -timeout 30m
```

可用 `POGO_SENTINEL_LIVE_MODEL` 指定已有模型别名，用 `POGO_SENTINEL_LIVE_OUT` 指定脱敏证据目录。测试会发出真实模型请求，有调用次数、Token 准入阈值和运行时限；Token 阈值不是精确费用或严格总量上限。不要将生产数据目录挂入测试环境。

这些用例用一个任意 TCP 协议作为受控来源，由模型自行编写脚本；它不是产品中的来源适配器。验收检查暂停授权、静默期间持续采集且无模型调用、条件触发、持久报告收据、重复投递、流断线续接和前次上下文。首次结果、修复后重试与验收预算中断必须分别记录。

`TestSentinelLiveHostStream` 是另一个对照用例：测试人员提供已知脚本，独立验证真实流式传输与真实模型唤醒。它通过不代表模型自主编写流式脚本已通过。工具链检查之外仍需核对报告的事实与推断，不能把事件中出现的字段声称为已经独立复核。

`TestSentinelLiveReportEvidenceContract` 只使用受控观察和真实模型，核验报告回执并保存语义审核材料，覆盖部分样本的 0、异构结构、明确分类规则、明细缺失和指令形状的来源文本。它不注册来源脚本，也不证明自主编写或采集通过；真实模型文字仍须独立审核，不能以执行成功代替语义正确。
