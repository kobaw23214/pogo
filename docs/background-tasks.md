# Web 后台任务与统一执行队列

2026-10-23。Agent 右侧原定时任务入口改为「后台任务」，包含「任务」「执行队列」「运行记录」三个视图。时间触发、手动立即运行和通用哨兵的条件触发共用持久执行入口。它们的定义、采集状态与执行结果仍由原来的模块管理。

## 定义与执行分开

一个任务可以反复产生执行。任务列表说明它是否启用、何时触发、是否正在监听；执行队列显示已经产生但尚未结束的某次工作；运行记录保存每次完成、失败、取消及中断的结果。

- 「暂停任务」阻止后续触发，不代表停止已经启动的 Agent 或内部流程。
- 「取消排队」取消这一条尚未开始的执行。未来周期和新事件仍有效。
- 「停止本次」先提交停止请求，界面显示「正在停止」，待执行退出才结束。此前的外部影响不会被撤销。
- 「重试」保留原记录，并新增一条关联的执行；结果不明的执行不会在服务重启后悄悄重跑。
- 「等待人工」仍是未结束的工作，不能通过编辑定义或再次运行制造重复审批。现有审批入口和权限规则保持不变。

条件监听空闲时不表示模型一直运行，也不显示执行中的旋转图标。采集脚本由已有 Sentinel supervisor 管理，只在命中事件后提交有限轮次的 Agent 执行。脚本继续负责连接任意来源、识别条件和形成观察；平台没有增加 HTTP、RSS 等来源专用业务分支。

## 持久化与恢复

统一记录位于 `<SessionDir>/task-runs/runs.db`，使用 SQLite WAL 和完整同步。`controller.lock` 限制同一目录只有一个调度者。任务的冻结执行请求、稳定触发键、原始绑定、执行状态和会话凭证都先写入，再启动模型。

目前同一进程最多同时启动两次后台执行，同一任务最多一次。采集脚本使用独立的既有容量限制；持续监听不会占满这两个模型执行位置。

时间触发键由定义摘要与原计划时刻组成；同一次时钟重放只得到同一条执行。`LastQueuedAt` 单独记录已接纳的时刻，不把排队或取消伪装成成功运行。它也修复队列提交与 `jobs.json` 更新之间的重启窗口。错过的周期仍按原来的有界补跑规则处理。

哨兵继续使用原生事件批次、稳定事件键和已确认的游标。原生批次先冻结，再向统一队列发布 `batch + attempt`。两个数据库之间没有跨库事务，因此发布必须幂等，并能修复半提交：例如队列已取消、原生批次尚未结束时，重新发布会恢复为「用户取消未开始的批次」，不会执行旧观察，也不会堵住后续新事件。

服务恢复时：

| 原状态 | 恢复行为 |
| --- | --- |
| 已排队 | 继续等待权限、容量和来源可用，再重新校验定义 |
| 正在执行 | 标记为中断，保留会话，等待核查或显式重试 |
| 已完成/失败/取消 | 保留原结果，不自动重跑 |
| 原生事件已有完成回执 | 按原回执对账，避免重新调用模型 |

去重防止重复准入，不构成外部系统副作用的 exactly-once 保证。脚本和业务写入仍应使用稳定键并遵循各自幂等约束。

## 维护与发布边界

发布维护标记出现后，队列停止认领新执行，已认领但尚未进入来源执行的请求退回排队。哨兵停止并回收采集进程，拒绝新 frame/ACK 和新批次，不改变用户的启用状态、Generation、确认游标或业务失败计数；解除维护后可按原状态继续。

维护标记不是瞬时全局停机。已经开始的 Agent/工作流及已经进入原 `RunOnce` 的定时执行必须先退出；发布检查需确认队列和原生执行均空闲，停止服务后再建立冷备份。不能仅写入维护标记便在线复制 SQLite 主文件。

## 权限与接口

在 Agent 能力配置中勾选内置 `background-tasks` Skill，会联动启用 `background_task`，取消勾选则一并停用；关联工具不能单独勾选。读取或引用 Skill 文档不会授予能力。旧配置保留原权限，只有主动切换该 Skill 后才采用整组关联；旧 `watch`、`watch_test` 入口继续兼容原来获准的操作，不会因此升级为完整后台任务权限。

新配置使用 `background_task` 的 `prepare/check/create/list/status/pause/resume/remove` 操作；哨兵中断批次还可用 `retry` 显式重试，该动作仅支持 `source:sentinel`，沿用原批次重试和审批语义。`watch_decide` 仅在宿主真正分发的哨兵事件处理中提供，不用于普通聊天、定时任务或等待流程完成。

`GET /api/tasks?agent_id=...` 是现有定义和执行账本的只读投影；`POST /api/tasks/{source}/{id}/pause|resume` 管理定义；`POST /api/task-runs/{id}/cancel|retry` 携带执行记录的 `revision`，拒绝过期操作。

公开 DTO 不返回原始请求载荷、所属账号绑定、采集游标、脚本参数或状态。只有当前账号与 Agent 的匹配任务可以操作。定义删除或重新绑定后，历史保留给原所属账号只读查看；结果链接也必须匹配原会话的账号与 Agent。

执行前再次校验当前定义、所属账号、Agent、脚本封存摘要和权限。排队不授予额外工具权限；Agent 任务沿用其审批策略，哨兵唤醒继续使用严格审批模式。暂停或修改任务也不会替换正在使用的输入。

## 本次范围

Web 内部时钟、Web「立即运行」、Agent 定时任务和哨兵条件唤醒使用持久任务队列。Agent 内部流程使用独立定义与历史表，并复用同一队列执行。普通任务的定时记录、编辑器及日志保留；退役平台流程的定时条目不再展示或触发。

独立 CLI / 操作系统调度器仍使用原执行路径。跨服务消息代理、多进程执行器与组织审批不属于该模块。Agent 内部流程的本人确认可以持久暂停并续跑同一 Run；逐工具审批的恢复边界仍由会话实现决定，不能由队列记录推断。
