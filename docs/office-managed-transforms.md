# Office 脚本修改与文件版本

本轮为代码实现，按用户要求未编译、未运行测试、未更新 Docker。后续发布前需要完成本文末尾的验证。

## 执行与发布

保留两种编辑引擎，共用文件发布记录：

- 原生 Word/Excel 命令修改共享画布，Agent 核对后显式保存。
- `docs_office action:transform` 使用已有 Bash 权限执行 Python，先处理副本，再提交原文件。脚本通过 `sys.argv[1]` 取得副本；工作区其他内容只读。

`transform` 复用 `batch_prepare → staged_path → batch_commit`。准备阶段冻结并保存当前画布，包括人工输入；执行成功、文件格式与原文件版本校验通过，才发布脚本结果。未打开的文件不创建编辑窗口。高级分步事务继续保留，适用于较大脚本和授权子代理处理副本。

Python 执行仍经过当前会话的命令审批与沙箱。只有 Office 权限、没有 Bash 权限的 Agent 不能使用此入口取得命令权限。脚本源码不在 Office 容器运行。普通命令和 Skill 使用原有网络与可写目录策略，仅增加已登记文档与私有版本目录的保护；受控 transform 则只允许写副本目录，不开放网络。

持久化执行回执先于脚本启动。相同 `operation_id` 绑定相同文件、脚本哈希和超时；不确定是否已运行的脚本不自动重跑。相同请求重试用于核对原执行和提交。副本执行成功、文件发布成功、画布同步成功分别表示，不相互冒充。

## 登记范围与保护

配置 Office 的 Web 服务登记已知的 Word/Excel 附件、浏览器下载、Office 打开和批处理源文件，历史附件在会话加载时补登记。登记按工作区和所有者持久化，不逐次扫描工作区。文件保护独立于 Agent 是否选择 docs 技能；没有该技能不能通过其他命令绕过已登记原文件，也不会因此获得 Office 工具或脚本权限。

已登记原文件在新启动的 Bash、声明式工具及子代理命令中只读；Write/Edit 拒绝直接覆盖。新建输出和未登记的一般文件不因此禁止写入。已启动进程的挂载权限不能追溯修改，不能据此声称拦截全部历史外部写入。

登记存储失败时，原保护清单会失效，旧子代理也经父级检查拒绝继续执行；完整登记恢复后才解除。已删除的文档仍保留登记，普通命令跳过不存在的只读挂载目标，不将整个会话永久锁死。该层针对 Agent 工具执行，不影响用户本地终端的权限。

## 文件版本

每次原生持久化保存、脚本提交或恢复保留完整的前后文件及系统生成的有界差异。记录按所有者与稳定文件身份归集，包含会话归属、保存发起者、执行引擎、脚本摘要哈希和执行 ID；保存发起者不代表所有差异的作者。

版本 UI 位于现有操作浮层的“版本记录”标签，按需加载，不增加常驻状态行或轮询。`action:versions` 同样可分页读取，最多20条/页。

当前语义差异只覆盖 Word 段落文本、Excel 已存储的单元格值与公式。系统明确返回覆盖范围、局限和截断标志，不将格式或图表变化误报为无变化，也不以模型描述替代实际差异。完整文件快照与这份有限摘要是两层独立数据。

每份文件最多50条记录、256 MiB保留预算；提交后清理不再引用的快照。不得承诺永久历史或用该预算代替备份。

## 恢复

`action:restore_version` 需要列表中的版本 ID、当前文件版本和稳定操作 ID。`restore_side` 可选 `before` 或默认 `after`。恢复使用同一文件事务，产生新的版本记录，不改写已有记录。

UI 在恢复前冻结输入、核对实时状态和文件身份；不清空 dirty 标记或强制刷新未知画布。磁盘版本变化时拒绝覆盖，人工未保存输入须先保存并重新确认。恢复完整文件会替换后续内容，不是选择性撤销 Agent 修改；编辑器的原生 Undo/Redo 仍独立使用。
