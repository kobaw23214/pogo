# Pogo 在线 Office 编辑

更新日期：2026-10-18。本文说明当前代码集成与隔离验证用法；不代表已部署到正式 Docker 服务。

Pogo 在文件面板中嵌入真实的 ONLYOFFICE Word / Excel 编辑器。用户输入和 Agent 的受控操作作用于同一个已打开的文档，包括尚未保存的内容。它不调用用户电脑上的 Microsoft Office，也不会通过改写磁盘旧文件模拟撤销。

## 从文件面板使用

1. 在当前会话上传文件，或选择工作区中的 `.docx` / `.xlsx` 文件。
2. 点击会话文件、附件或工作区中的 `.docx` / `.xlsx`，直接进入 ONLYOFFICE。编辑器连接与能力验证完成后，可在画布内输入、选区、修改表格；重复点击同一文件复用原窗口，不重建画布。
3. 在同一会话启用内置 `docs` 技能，再要求 Agent 修改该文件。Agent 打开已在此会话编辑的文档时复用已有画布；新的文档通过主界面的打开事件与轮询显示。
4. Agent 默认在修改、撤销或重做后读取核对并显式保存；用户要求暂不保存时遵守用户要求。也可手动点击编辑器上方「保存」。只有显示「已保存版本 N」才表示当前导出文件已写回工作区。
5. 需要验证保存结果时，先保存，再关闭并重新打开文件。新编辑会话读取的是已经写回的文件；普通的重复点击和刷新保留原画布。

可以这样提出任务：

> 使用 docs 技能，读取我当前打开的 uploads/合同.docx。把其中唯一的“付款期限为 15 天”改成“付款期限为 30 天”，保留我尚未保存的其他修改，完成后保存。

> 使用 docs 技能，读取 uploads/销售.xlsx 的“销售”工作表，核对 C2 当前值后修改为 5，保留其他单元格和公式，再保存。

Office 未配置或一般连接失败时，`.docx` / `.xlsx` 入口显示原因与重试。若文件由另一个窗口占用，仍可明确进入「查看已保存版本」：Excel 使用只读表格，Word 使用文件正文预览，均不包含原画布未保存的修改，也不获取编辑权。独立文档解析工具仍可使用。在线编辑目前仅支持 `.docx` / `.xlsx`；旧 `.doc` / `.xls` 继续沿原有预览或明确的格式限制处理，不会出现虚假的可编辑状态。宏格式和其他 Office 类型不通过此入口编辑。Office 编辑单文件上限为 20 MiB。

## 打开等待与恢复

打开界面依次显示服务检查、编辑会话、编辑器资源、文档画布和 Agent 连接的进度，以及本阶段已等待秒数。耗时较长会提示继续等待；不再因旧的20秒或25秒限制造成提前失败。

Pogo 控制的打开阶段预算均至少5分钟：服务恢复、SDK加载、画布就绪和插件能力握手为300秒；客户端请求、内部HTTP连接及Pogo网关响应头使用310秒，给阶段结束后的回执保留传输余量。后台健康采样继续快速返回，但短暂的未就绪结果不会直接阻止打开；真实打开使用独立5分钟等待和共享探活。容器启动等待至少300秒，Docker健康检查启动宽限360秒。明确的权限、配置或文件错误可提前返回，无需人为等满5分钟；文档修改和保存使用各自既有期限。

网络错误允许最多3次有界重试，始终复用原编辑器实例身份。丢失打开响应时，通过原POST找回同一会话与启动凭证；不自动抢占其他实例或重放文档修改。插件就绪通知重复发送直到同身份确认，握手重试只查询能力，不重复执行编辑。

失败后仅能释放当前实例完全未使用的启动占用。释放前同步锁定输入并核对排队状态，服务器确认释放前保留原画布。已有画布、人工输入、在途操作或结果未知时不自动销毁、刷新、关闭或另建编辑器；保留原实例供重连。未知打开结果和未确认释放会阻止普通导航丢弃原实例身份。迟到的旧请求只能清理自身尚未被采用的占用，不能销毁新生命周期中的窗口。

本轮已执行针对性控制器、网络、插件协议及后端测试；真实ONLYOFFICE加载、在线负载及人工输入的线上体验仍需发布后确认。本轮没有构建或部署Docker镜像。

## 处理内置浏览器下载的文件

在当前会话的内置浏览器登录其他系统并下载文件，原 Chromium 处理带登录态的 HTTP 下载或网页生成的 blob 文件。后台只读取已完成的受控下载，不重新请求网站，也不读取用户电脑的下载目录。

下载通过附件类型与大小检查后，进入当前会话的 `uploads/browser/`，出现在会话文件列表和浏览器工具栏的下载列表。点击已完成文件沿用同一工作区打开路径；不会因为下载自动跳页、切换控制权或打开 Office。状态通过现有会话事件流更新，前端不增加轮询。

Agent 使用 `browser {"action":"downloads"}` 查看结果。只有 `state:saved` 与 `path` 同时存在才表示文件已导入，可以将该路径交给文档工具或 `docs_office open`。例如：“处理刚从业务系统下载的 Excel，核对销售额公式、保留原有其他内容，完成后保存。”列表是有界近期记录，历史文件继续保留在会话文件中。

单个下载受当前附件上限与 worker 32 MiB 上限中的较小值限制，进入 Office 后还要满足 Office 自身限制。相同文件名的不同下载分开保存；导入重试不会覆盖已被用户或 Agent 编辑的文件。失败明确显示原因。关闭浏览器会话会取消未完成下载，不应把仍在下载的文件当作已保存。

Agent 收尾检查根据本轮真实成功修改和持久化回执，最多提醒一次尚未确认保存的文档。它不代替 Agent 偷偷保存，不处理纯人工修改的其他文档，也不会把失败或结果未知报告为保存成功。

## 保存、撤销与会话状态

撤销和重做使用编辑器的**整体原生历史**，既包含 Agent 操作，也可能包含用户输入。它们撤销的是当前全局最后一步，不是指定某个 Agent 改动的选择性撤销。读取当前内容与拒绝过期写入必须保留原生历史和选区；只有固定扩展握手通过后才开放这些能力。

画布发生变化、工具返回修改成功、文件已经保存是不同状态。保存只有一条写回通道：公开 `DocEditor.downloadAs` 导出当前编辑器内容，经 `onDownloadAs` 回执交给 Pogo，后台校验来源与文档身份后原子写回文件，返回保存版本。ONLYOFFICE 自动保存/关闭回调不是工作区保存回执：签名、文档身份和导出地址通过核对后，先持久保留独立恢复副本再确认接收，不能把它记为原文件已保存。取回或记录失败时不返回成功确认，让编辑服务保留可恢复产物。导出期间暂时锁定当前编辑器输入，完成或失败后解除。

未保存修改、在途操作或结果未知时，返回预览、关闭页签和切换文档会受到保护。不会在卸载组件时偷偷保存或丢弃修改。正常离开先等待后台确认关闭，再销毁画布；浏览器刷新使用同源、同实例的受限清理请求，只有干净且无在途操作的旧会话才可关闭。编辑状态仍绑定打开时的会话，切换聊天不会给其他会话重新分配文档身份。

同一份文件允许多个窗口查看已保存版本，但仅一个窗口拥有编辑权。查看、状态查询、预览刷新均不续编辑权。编辑窗口每 10 秒发送具备实例和租约代际的心跳，服务端租约为 90 秒；客户端长时间未获得确认时暂停输入并保留画布。在线编辑器不能被另一个窗口强行接管。

失联且干净、没有在途操作或未知结果的旧编辑器可显式接管；服务端在文件锁内重新核对旧 session、generation、dirtyEpoch、leaseEpoch 和磁盘版本，再签发新的 session/key/凭证。旧窗口的心跳、修改、导出和卸载消息不能更改新窗口。丢失接管响应时使用相同实例与完整原请求找回同一启动结果，不生成第二个编辑器。

失联但有未保存内容的文档，先封存旧编辑连接，再向编辑服务请求带关联身份的恢复快照。只有恢复文件通过文档、大小、内容哈希核验并持久化，才允许在保留副本的前提下接管已保存的原文件。界面明确说明：恢复副本独立保存，接管编辑的是工作区已保存版本，尚未传到编辑服务的离线修改不能保证包含在副本中。恢复未知或失败不会自动清除 dirty、推进 persistedEpoch 或覆盖原件；也可选择「编辑已保存副本」创建独立文件继续工作，保留原异常占用与证据。

若原恢复请求没有得到确定结果，而服务端确认存在可查询的旧编辑身份，用户可显式「查找引擎恢复副本」。这一步只查询该文档精确 key 的保留产物，不重复发送保存命令，不切换恢复 ID，也不覆盖工作区文件。查询有次数与间隔限制；下载通过身份、来源、格式和内容校验后，仍保存为独立恢复副本。已有副本就绪后才到达的关联保存回执，若包含另一份快照，先独立持久保存为补充副本再确认接收，原副本和接管条件不变。来自编辑服务的副本只证明服务已接收到的内容，不能证明旧窗口尚未传出的离线修改也已恢复。

编辑权、未保存状态和恢复副本记录保存在模型工作区之外的私有目录，并在应用重启后恢复为失联占用。它们不是未保存字节本身：不能把记录仍在当成草稿完整恢复。旧版本升级前留下的异常记录只有在保留真实可观察证据后才能导入，不伪造旧版本没有的回调身份。

用户不希望另建副本时，可显式选择「清理占用」并确认放弃旧窗口尚未写回的修改，随后继续编辑同一路径的原文件。若旧窗口可能仍在线，还必须确认中断它的编辑。清理沿用当前磁盘中已经保存的内容，不覆盖文件、不删除已有恢复副本，也不把旧窗口的未保存状态记为已保存。后台持久保留原状态与确认记录，再封存旧写入身份、签发新的编辑身份；旧窗口和迟到的保存结果不能覆盖原件。

清理请求必须匹配确认时的文件版本、旧编辑实例及其状态代际；确认期间发生新修改、保存或编辑权变化时，需刷新状态并重新确认。仍在进行的保存、命令或批处理不能直接清理。丢失响应时只用相同请求找回结果，不自动重复执行新的清理。此入口由用户主动操作，不作为 Agent 遇到文档占用时的自动降级策略。

编辑界面默认自动写回工作区：输入静止后尝试保存，输入法组合输入、持续键入和其他正在执行的操作不会被自动导出打断。手动保存与原生画布中的 Ctrl+S / Cmd+S 共用同一写回流程。文档详情可关闭「自动写回工作区」以保留草稿，未保存保护仍然生效。编辑器发出“内容已送达编辑服务”事件只触发写回调度；界面仅在真实原文件写入得到确认后显示“已保存到工作区”。

### 文档身份与恢复

Studio 文件卡片、工作区文件树、Agent 打开及发现接口共用账号工作区内的规范 `path` 与稳定 `fileRef`。旧的本账号 `users/<owner>/...` 路径只能经过服务端授权解析；不通过路径后缀猜测同一文件。`documentId`、编辑会话 ID 和 `bootEpoch` 是当前执行身份，不能替代稳定文件身份。

打开配置只在签名完成后领取执行实例。后续资源或引擎加载失败，客户端可用本次领取的启动令牌释放尚未使用的实例；后台要求实例、文件和服务身份均匹配，并且没有画布、修改、待办或未知操作。原生画布出现即上报 `mounted`，插件尚未就绪也受到保护，不会用启动期清理关闭它。

旧编辑会话确实不存在时，新页面按同一授权文件路径重新打开。已挂载窗口检测到旧会话失效，只在干净且没有在途操作、未确认输入或保存时有界重连。存在人工输入或未知操作则保留原画布，暂停旧通道并显示恢复说明，不重建窗口掩盖未保存内容。正常重复点击复用原窗口，不触发重连或销毁。

同一聊天的并发冷加载只构造一个正式 Session；未发布临时实例的清理不能撤销正式实例的 Office 身份。闲置退役完成前，同一聊天的下一代实例等待旧实例关闭；其他聊天仍可加载。真正删除、关闭及身份撤销保持生效，人工未保存内容继续阻止闲置驱逐。

### 操作超时与自动恢复

纯读取的超时、取消或回执丢失不会把文档锁成不可用，也不会标记为修改。`READ_TIMEOUT`、`READ_CANCELLED` 或 `READ_FAILED` 后可用新操作 ID 重新读取当前画布；失败或过期的读取回执不能用作后续写入条件。

修改、历史操作或导出的结果不确定时，保留原画布及原操作回执，进入 `recovery.state: checking`。查询与读取仍可使用，新写入、保存或批处理最多自动等待恢复 15 秒。插件核对原生执行的实际回执并通过原生队列屏障，前端再将同实例、同恢复版本的完整确认交给后台。确认已结束但结果仍不明时，补一次新的真实读取后恢复操作。不会换 ID 重放未知修改，也不会把恢复当作已经保存。

前端轮询可确认已完成的读取或已知操作，解除因回执丢失留下的占用；恢复消息不依赖这份占用才能发送。导出只有原下载回调及写回通道结束后才可确认恢复，单纯超时不能证明导出结束。短暂断网重连复用同一画布及插件，人工新输入仍保持未保存状态。

### 批量格式修改

边框、样式等批量操作使用 `batch_prepare → staged_path → batch_commit`。准备阶段先将人工与 Agent 的共享画布保存，冻结文档后只允许命令工具处理隔离的暂存文件。提交核对原文件身份与版本，再原子更新文件，原窗口加载并验证新的文档版本。失败时保留原文件，使用 `batch_abort` 释放事务；结果未知时查询 `batch_status`，不直接改写原文件来绕过保护。

### 同一文档的操作顺序

每份文档独立排队；已有修改、撤销、重做和读取依次执行，保存作为前序操作后的屏障。保存到达队首时捕获当前修改版本，导出与提交成功后才确认对应版本已写回。同一待保存内容的重复保存请求合并成一次导出，每个操作 ID 的回执仍保持幂等且受记录额度限制。

保存排队时显示等待状态，尚未派发导出不会锁住人工输入。保存入队后新的 Agent 修改返回明确的 `SAVE_IN_PROGRESS`，应等本次保存完成再重新读取、修改。真正导出期间仅短暂暂停当前文档输入，其他文档可以继续操作。前序操作失败、结果未知、前置条件冲突或文件提交冲突时，保存不假报成功，保留画布并给出具体原因。

一个共同保存调用者取消等待，不会取消其他调用者共享的已派发保存。导出阶段使用自己的超时，旧的排队计时器不能误取消新阶段。保存后的新人工输入继续标为未保存；重试旧操作 ID 只获取旧保存回执，不表示后来的输入已经写回。

外部程序改动磁盘文件时，刷新文件列表会保留现有画布并提示变化。保存会核对原文件的身份与内容，冲突时拒绝覆盖；应先核对当前画布和磁盘内容，不要重复发送写入来消除错误。

每个编辑会话的命令与保存共用操作记录额度：最多 512 条普通记录、16 MiB 参数及回执预算；在途回执先预留空间，单次回执不超过 1 MiB。额度满后另保留一次最终保存，再应关闭已保存文档并重新打开新会话。同 ID 重试只读取既有结果，不重复派发。最终保存额度用完、仍有新修改或保存结果未知时，画布继续保留，关闭仍受未保存保护；不会通过清空记录、重复写入或强制关闭绕过限制。保存提交期间再次核对目录、文件身份与内容，目录被移走或替换也会拒绝写回。

## 运营者启用配置

Office 默认关闭。全部相关环境变量为空时，Pogo 沿用原来的只读预览。设置配置后，启用状态由 `GET /api/office/config` 返回；配置不完整或不合法时 Office 编辑不可用，Pogo 其他功能仍可启动。

| 环境变量 | 用途 |
| --- | --- |
| `POGO_OFFICE_SERVICE_URL` | Pogo 后台访问 Office adapter 的私有来源，必须提供下述固定 SDK 扩展；不向客户端暴露。 |
| `POGO_OFFICE_BROWSER_URL` | 旧配置兼容项，仅在 Service URL 省略时作为私有上游；新配置应省略，不再用它生成客户端地址。 |
| `POGO_OFFICE_PUBLIC_URL` | 可选的旧配置兼容项，不再决定客户端地址或允许来源；只为旧配置保留服务端 Fetch URL 的缺省值。 |
| `POGO_OFFICE_FETCH_URL` | ONLYOFFICE 能访问的 Pogo 文件和回调来源；新配置应明确填写容器内部地址，如 `http://pogo:7777`。 |
| `POGO_OFFICE_JWT_SECRET_FILE` | 与 ONLYOFFICE 配置一致的 JWT 密钥文件路径；文件内容需为 32–8192 字节且不含内部换行。 |

服务配置 URL 必须是完整的 HTTP(S) origin，不能含用户名、密码、路径、查询参数或片段。客户端来源取当前已经认证并校验的页面地址，SSH 转发到 `http://localhost:8080`、直接访问部署端口或经 HTTPS 反向代理不要求重配 Public URL。Fetch URL 面向编辑服务的网络环境，不跟随客户端地址；容器不能通过用户电脑的 `localhost:8080` 获取文档。反向代理应保留浏览器访问的 Host。

以下是**已有隔离服务**的配置示例，只说明地址关系，不创建或部署容器：

```sh
export POGO_OFFICE_SERVICE_URL=http://127.0.0.1:19898
export POGO_OFFICE_FETCH_URL=http://host.docker.internal:19897
export POGO_OFFICE_JWT_SECRET_FILE=/isolated/office/jwt-secret
```

示例中 `19897` 是 Pogo Go 服务，`19898` 是已核对 SDK hash 的扩展代理，其上游是隔离 DocServer。浏览器可直接访问 Pogo，也可通过一条 SSH 转发访问本地 `8080`；客户端请求跟随这个实际入口。正式配置只公开所选的 Pogo Web 端口，Service URL 使用容器网络地址 `http://pogo-office:8080`。密钥文件由运营者提供，不将密钥写入文档、模型消息或命令参数。Vite 只作为后台开发资源上游，隔离验收通过 Go 入口访问，以便检查所有客户端请求是否保持单一来源。

### 单一 Web 入口

客户端配置固定返回相对地址 `/office/editor`。编辑器脚本、iframe、字体、Worker、编辑长连接、原生导出均由 Pogo 网关转发到私有 Office adapter；文档文件、插件桥、操作队列和保存回执仍使用 Pogo 的已有入口。前端拒绝跨来源的引擎地址，不保留直连容器的备用路径。

插件桥地址和插件 manifest 同样使用根相对路径。打开编辑器时，Office 专用请求声明当前页面来源，后台要求它与实际请求 Host、浏览器 Origin 一致，随后绑定到当前文档实例和网关凭据；该声明不改变内部上游。网关按绑定来源签名转发，导出只接受当前实例来源或固定内部服务，并且仍需通过文档缓存 key 校验。账号相同而访问来源不同的实例不会共用来源绑定，Cookie 名称也按来源区分。不会通过修改全局 Public URL 适配某一次请求。

网关使用已认证的文档打开请求签发有时限、HttpOnly 的编辑器访问凭据，只开放固定资源目录和当前账号所持文档的动态路径。账号 token 和 Cookie 不转发给 Office；编辑器 JWT 保留。注销、账号凭据变化或文档关闭会撤销相应编辑连接。Service Worker 只覆盖对应版本的编辑资源，不能接管 Pogo 页面。导出回执需要匹配当前保存操作、实例和文档缓存身份，后台才获取文件并写回。

网关采用连接复用和流式 HTTP / WebSocket 转发，编辑画布仍由客户端原生网页渲染。正式模板不发布 Office 宿主端口。既有双端口部署需要显式迁移配置并同时更新 Pogo 与 adapter；本轮不执行迁移或发布。

当前代码不自动安装编辑引擎，也不自动修改正式容器。固定扩展的加载、独立 staging 与升级要求见 [Office runtime README](../office-runtime/README.md)。

## Agent 工具合同

Web 会话启用内置 [docs 技能](../skills/builtin/docs/SKILL.md)，且后台配置 Office 时，提供模型工具 `docs_office`，工具目录名称为 `docs.office`。离线解析工具继续保留；没有在线工具时不能声称已修改当前画布。

| action / operation | 用途与要求 |
| --- | --- |
| `list` | 列出当前身份、当前会话可操作的文档，查看 ready、dirty、pending、blocked、版本及能力。 |
| `open` | 用工作区 `path` 打开 `.docx` / `.xlsx`；已有同会话文档复用原 session。 |
| `command: capabilities` | 查看当前引擎实际验证的能力。 |
| `command: word.read` | 读取当前全文、选区文字和段落，不改动历史或选区。 |
| `command: word.replace` | 使用 `search`、`replacement`、`expectedReadId` 和 `expectedCount:1` 核对并替换唯一目标；读取引用来自同一 session 的成功 `word.read` 回执顶部 `operationId`。兼容完整 `expectedText`，两者只能选一。 |
| `command: sheet.read` | 用 `sheet` 和 `range` 读取 `inputs`、计算值 `values`、显示值 `display` 与工作表名称。 |
| `command: sheet.apply` | 用同范围的 `expectedInputs` 与 `inputs` 完整矩阵核对并写入；公式作为输入字符串保留。 |
| `command: history.undo / history.redo` | 执行全局原生历史操作。Excel 的 `{sheet,range}` 只指定结果观察范围，不限制撤销范围。 |
| `save` | 导出、写回并返回已确认版本。 |
| `close` | 关闭干净会话；未保存、在途或结果未知时拒绝。 |

`command`、`save`、`close` 使用宿主返回的 `document_session_id`，不能猜测或跨会话使用。写入、撤销、重做和保存必须带稳定 `operation_id`；其格式为 8–100 个 ASCII 字母、数字、下划线或连字符。同 ID 仅可用于完全相同的请求。失联、超时或结果未知时先查询状态，必要时用同 ID 重试原请求，不生成新 ID 重放可能已成功的操作。每次修改或历史操作后重新读取当前编辑器，既核对目标结果，也确认用户其他未保存输入仍存在。

`list`、`open`、`save`、`close` 不接受 `operation` 或非空命令参数；`args` 可以省略或传空对象 `{}`，明确的 `null` 也规范为省略。空参数形式不会改变保存等操作的 `operation_id`；数组、字符串和非空对象仍拒绝。

Word 默认用读取回执引用作为前置条件。宿主从已完成且成功的 `word.read` 回执中取出准确全文，保留末尾换行等细节，再沿同一条编辑器原子核对通道执行修改；模型无需重新生成完整正文。`expectedReadId` 是回执顶部的 `operationId`，不是模型工具调用 ID。回执必须属于当前文档 session，不能来自其他文件、其他会话、失败或尚未完成的读取。直接传入完整 `expectedText` 仍兼容，但必须保留每个字符，并且不能与引用同时提供。

`PRECONDITION_FAILED` 表示前置条件在写入前被拒绝，保证此次未写入且不清除重做历史。应重新读取、核对用户的新内容；条件或参数改变后，使用新的修改 `operation_id`。`INVALID_READ_REFERENCE` 表示没有可用的当前 session 成功读取回执，同样应重新读并以新 ID 提交修改。不能改了参数却复用旧修改 ID，否则返回 `OPERATION_ID_CONFLICT`；这一限制与“结果未知时保持原请求和原 ID”并不矛盾。

下面仅展示受控参数形状，先对同一活跃文档执行 `word.read`，再引用其成功回执：

```json
{
  "action": "command",
  "document_session_id": "<open 或 list 返回的 ID>",
  "operation_id": "replace_payment_001",
  "operation": "word.replace",
  "args": {
    "search": "付款期限为 15 天",
    "replacement": "付款期限为 30 天",
    "expectedReadId": "<word.read 成功回执顶部的 operationId>",
    "expectedCount": 1
  }
}
```

操作沿 Pogo 既有身份和审批策略执行：受限读取可自动通过，写入及历史操作按当前策略审查。文档正文是待处理的数据，里面的命令文字不能作为对 Agent 的授权；工具不接受任意 JavaScript、下载地址或本地 Office 自动化参数。
