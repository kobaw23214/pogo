# MCP 第一阶段实施与验收（2026-09-21）

本阶段完成连接配置导出、MCP 传输与日志正确性修复。完整的双向 MCP 监控中心和 Skill 执行监控属于后续阶段，本次未实现。

## 使用入口

- 设置 → MCP → 建立（服务端）→ **导出本机接入配置**：填写接收方可访问的 URL，选择目标格式，预览、复制或下载 JSON。
- 设置 → MCP → 接入（客户端）→ **导出连接**：勾选已保存的连接，再选择目标格式。
- 支持 Pogo、Claude Code、Cursor、VS Code。接收方需要自行设置列出的环境变量。目标格式不支持的字段会明确提示；无法安全转换的连接会被跳过。

配置读取已保存的快照；未保存的表单不参与导出。本机导出展示有效的启用、认证、策略和工具范围，不修改这些设置。凭据替换覆盖 Bearer 字段、敏感请求头、环境变量，以及可识别的 URL/参数凭据位置。任意 shell 脚本或自定义非敏感字段里的隐含凭据不属于通用语义分析范围。

格式与迁移说明见 [mcp-export.md](mcp-export.md)。

## 正确性修复

- 客户端注入的 Bearer 和自定义请求头绑定到配置 URL 的 origin（协议、主机、有效端口）；携带这些配置的跨源重定向停止跟随。
- 日志只旁路采样处理器实际读取的请求数据，不截断转发的请求体，也不在处理器结束后额外排空未读数据。
- 日志分别记录 HTTP 状态、JSON-RPC 结果和工具结果。HTTP 200 中的 JSON-RPC 错误或 `isError=true` 会进入错误分类。
- 分类核对响应 ID，支持 JSON 和完整 SSE 事件；截断或无法确认的结果记录为未知。该能力仍基于有限响应采样，并非工具执行链路的完整追踪。
- 关闭正文采集同时关闭请求和响应正文的存储；结构化结果分类继续保留。SQLite 自动增加结果字段。
