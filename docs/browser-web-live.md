## 会话恢复与引用图标（2026-10-09，代码更新）

重新进入会话时，前端先完成不带旧标签绑定的浏览器发现，再连接当前实例的真实标签。只有带会话与请求代次校验的完整发现结果可替换 `context_ref`；后台标签的迟到观察不能切回旧实例。失效实例的非空网址保留为中性恢复记录，默认选中当前有效页面；用户主动查看恢复记录时，轮询不会抢走选择。“重新打开”明确创建新 Page，再对新页取得租约并导航一次，不沿用旧租约、不重放旧操作。`BROWSER_CONTEXT_CHANGED`、`BROWSER_TAB_CLOSED`、`BROWSER_SESSION_EXPIRED` 可触发恢复；仍在执行的操作、断点及结果未知等其他 409 不走此路径。

引用图标属于会话展示元数据，与浏览器连接分开保存。会话授权的 `GET /api/sessions/{sid}/browser/icons` 从独立档案读取已观察到的图片，不启动 Chromium、不访问被引用的网站。正文优先采用原工具结果中的图标，其次采用同会话、精确网页 URL 对应的已保存图标；网页加载失败、标签关闭或实例重建都不删除这份历史信息。以前从未捕获过的图标，须在后续真正打开网页并观察到图标后才能补存。

这套恢复处理不承诺恢复已经销毁的页面 DOM、表单、滚动位置或 Cookie，也不改变现有浏览器回收策略；部署验收需单独记录。

更新：2026-10-08。当前产品方向是 **Docker Web 版 Pogo**：Chromium 留在浏览器容器中，用户在普通浏览器里的 Pogo 页面查看和接管。Electron 桌面实现保留作可选实验参考，不是使用 Docker Web 的前提。

本文描述已部署的实时通道、逐标签控制和桌面 viewport。本机最新正式镜像为主服务 `1e3cf69e3d67` 与 worker `fff82d8cf752`；其他服务器仍需独立部署。Docker 候选、正式部署及人工体验验收分别记录，不能把此前桌面窗口的手感确认移用到这里。

## 逐标签控制与桌面 viewport（已部署）

2026-10-08 的后续更新已将人工接管从整个 BrowserContext 改为当前标签页。点击 A 的“接管”只取得 A 的租约；Agent 可以在另一张由 Agent 控制的 B 中继续任务，也可以明确新建标签。接管 A 会阻止后续针对 A 的 Agent 动作，并等待 A 已派发的原子动作结束；不会取消 B 的动作或直接取消整轮模型。此处描述本次正式部署协议。

- `POST /api/sessions/{sid}/browser/control` 必须同时携带 `context_ref`、`tab_id` 和模式；缺少标签的旧请求返回 400。成功响应的 `viewed_tab` 必须与请求一致，只有人工接管回执返回该标签的租约。
- state 的 `control` / `control_epoch` 描述 `viewed_tab`；`active_tab` 仍是 Agent 执行目标。`tabs[]` 只公开 `id/url/title/control/control_epoch`，不公开任何标签的 lease。前端按窗口、会话、context、标签保存内存租约，切换 Sheet 不把 A 的授权带到 B。
- 标签控制切换只改变该页 `control_epoch`；`generation` 仅在 context 取消或重建时变化。人工输入不永久切换 Agent 的 `active_tab`，弹出的页面继承发起页控制归属，避免 Agent 获得人工弹窗。
- Agent 先调用 `tabs` 判断任务是否依赖人工正在操作的页面。独立任务可用 `{"action":"tab","tab_action":"new","url":"https://example.com/"}` 新建并选择页面；已有 Agent 页用 `{"action":"tab","tab_action":"switch","target":"t2"}`。明确要求继续人工当前页的任务应等待交还，不能通过新标签绕开页面控制。

同一会话的标签仍共享 BrowserContext，包括同源 Cookie 和存储。另开标签通常能复用站点登录态，但不能视作另一个隔离账号；一页的登录、退出或账号切换也可能影响其他页。不同 Pogo 会话仍使用各自独立的 context。

默认保留桌面网页布局：实际 viewport 宽度至少 1280、高度至少 720 CSS 像素；宽视图可扩展至 2560 × 1600，窄侧栏按比例展示，不因面板变窄而把网站切成平板布局。沉浸模式通过现有 WebSocket 请求调整真实 viewport。人工持有目标页租约时可调整；Agent 控制且空闲时允许仅用于显示的 resize，不授予键盘、点击或滚轮权限。存在执行中的动作、未确认结果或过期帧时延后，待新状态和帧确认后再调整。

并发范围有明确边界：WS 键鼠输入使用目标页队列，可与另一个标签上结果已知的 Agent 动作并行；地址栏和书签的 HTTP 人工导航仍经过 Go 串行执行队列，可能等待当前 Agent 动作。未处理的模态弹窗及动作、取消或输入释放结果未知时仍需先解决；不能用新开页绕过这些限制。未知结果会封锁整个 context，另一页的接管不能解除该封锁；确认旧 context 清理完成后才能恢复，也不会重放先前输入或业务请求。

完整 Go Web 包回归及 race 检查、运行时 207 项测试、前端 3731 项测试通过。真实 Docker 网页验收 15 项通过：Agent 控制下切入沉浸模式，viewport 与页面自身 innerWidth/innerHeight 同步从 1280×1600 变成 2084×934。真实 GLM-5.3 在人工持有 t1 时新建 t2 完成任务，t1 地址与控制代次保持不变，测试提交和回执各一次；工作流检查也通过。

## 同一个浏览器，两种控制入口

Agent 沿用 `browser-use → BrowserGate → Go 会话桥 → Playwright/CDP`，执行导航、DOM 定位、Network/Console 观察和调试。人工接管从 Web 面板取得租约，经专用 WebSocket 发送输入。两者最终操作同一 Chromium 中、同一会话绑定的 Page，共用网站登录态、标签、控制权和取消边界。

每个 Pogo 会话仍有独立 BrowserContext。查看其他 Sheet 不改变 Agent 当前执行标签。浏览器容器不嵌入另一个网站代理，也不启动供人操作的第二个 Chromium；目标网站保持原始 URL、Cookie、CSP 和导航行为。

主服务和浏览器 worker 两个必要容器属于同一正式部署，不代表新旧两套执行器。Electron 的 WebContentsView 不是本轮 Web 显示组件，Docker Web 不通过本机桌面 worker 执行。

## 画面与输入

正常查看使用 CDP `Page.startScreencast` 的连续 JPEG，经鉴权 WebSocket 推送。它是远端 Chromium 的画面传输，**不是 WebRTC 视频，也不是本机原生网页显示**；没有使用 VNC/RFB。网络、JPEG 编解码和客户端显示仍有成本，不能据此承诺等同本地 Chrome 的延迟。

客户端解码后确认帧。服务端及时确认 Chromium 编码事件，只保留一张已发送待确认帧和一张最新待发送帧，丢弃中间积压画面；不会在恢复连接时追赶旧截图。每 300 ms 检查并按变化推送状态，正常操作不再轮询截图。加载指示、连接状态、Agent 忙碌和帧是否可交互分别处理。

人工输入直接派发到该 Page 的 CDP `Input.*`，仍经过目标页输入队列与租约校验，但不在每次按键或鼠标移动后等待 DOM 快照：

- 拖动保留 pointer down/move/up，只有中间移动可以合并；滚轮使用实际坐标和增量。
- 普通文本、粘贴和输入法提交只插入一次；输入法组合期间不把候选按键重复发往网页。
- Enter、Backspace、Tab、方向键及受支持的编辑组合键走按下/释放事件。
- 人工持有租约时，可将真实页面 viewport 调整到面板尺寸；当前范围为 320–2560 × 200–1600 CSS 像素。
- 正常短暂输入不会被推送成 Agent 忙碌，从而打断进行中的拖动。结果超时未确认时才阻止继续输入。

Web 客户端不会缓冲后重放输入。断线重连申请新票据并等待新帧；已有租约也必须重新匹配当前控制代次，不能沿用旧画面坐标继续动作。

## 鉴权、控制与恢复

Web 客户端先通过已认证的会话 API 申请 30 秒、单次使用的连接票据。票据绑定当前用户、会话、同源地址、context 和标签；Go 只向私有 worker 转发其服务凭据，不把 worker token 或长期用户凭据放进 WebSocket URL。

每个写事件携带严格递增的序号、当前租约、generation、control_epoch 和已确认的 frame_id。坐标依据顶层文档与 viewport 身份核对；普通 DOM 变化不应使一次持续拖动失效。每个目标页同时只有一个实时连接能写输入；其他页可以有独立的人工输入或 Agent 操作。显示尺寸调整不授予输入权限。

交还、重新接管、取消、页面关闭和连接断开都会使排队输入失效并释放按下的键或鼠标。释放结果无法确认时，页面保持阻塞，Agent 和人工都不能接着操作；必须显式取消，关闭不确定的旧页面后恢复。已经提交到网站的业务动作不能撤回，也不会自动重发。

## 元素引用仍是只读观察

进入引用模式时，暂停更新展示画面和转发人工输入，取得一次有严格版本的 `/frame` 观察，再沿用 `/pick` 的只读命中、高亮和引用链路。网页本身并未被冻结；若它导航、滚动、布局或文档版本变化，选取必须失效并重新观察。退出后恢复连续画面。

这个单次截图用于核对引用，不是第二套浏览器执行器，也不恢复普通操作的截图轮询。引用结果仍是只读 `pN` 观察，Agent 真正操作前应重新取得可执行元素定位。表单值、密码和隐藏字段不会因此进入引用摘要。

本地真实 Chromium 的运行时测试已验证连续画面、Unicode 文本一次插入、textarea Enter/Backspace、原生 range 控件拖动、动态 viewport、重复序号不重放、租约交还、断线释放按键、帧背压及多个观察窗口。另有释放失败与输入超时的故障注入测试。当前运行时完整测试为 207/207；正式部署验收另有下列记录，不代表所有真实网站均已验收。

前端与 Go 的实现分别覆盖输入法提交去重、丢帧处理、一次性票据和鉴权代理。浏览器合成 composition 事件或 CDP 插入 Unicode，只能验证协议与组件行为；**Docker Web 下用户常用的物理中文输入法、真实鼠标长距离拖动和主观跟手性尚未由用户确认**。此前用户确认的是独立 Electron 窗口，不能作为本方案通过的证据。

当前尚未承诺完整远程桌面能力。上传/下载交接、远端选择复制到本机剪贴板、系统权限窗、硬件认证和各类网站验证码需要各自验证。容器重启后的登录态持久化也不能从桌面 profile 验证中推定。人工 Web 面板尚未嵌入完整 Chrome DevTools frontend；Agent 的通用 CDP 能力继续保留。
