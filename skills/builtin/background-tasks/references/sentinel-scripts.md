# 编写、试运行与注册哨兵脚本

仅在选择 `source: sentinel` 时读取。来源连接、认证方式、查询和业务触发条件
由脚本实现；宿主提供通用执行、协议和持久化，不要求使用特定来源类型。

## 准备与实现

在工作区独立子目录中选择入口，Python 使用 `.py` 文件：

```json
{"action":"prepare","source":"sentinel","script_path":"watchers/source-observer/main.py","mode":"poll"}
```

按回执中的 SDK API 说明编写入口和必要依赖。已有入口不会被模板覆盖；SDK
内容冲突时保留原业务代码，在新目录准备兼容版本，不覆盖旧封存注册。
`prepare` 的模板故意没有业务实现，不能把准备成功当作来源已接通。

Python 使用提供的 `pogo_watch.py` 中 `Watcher` 和 `event`。不要改写协议 SDK、
手工拼装帧或另建 ACK 框架。其他语言按当前工具声明实现同一个协议。

- **poll**：执行一次来源查询，计算事件与新状态，最后 `emit` 或 `checkpoint`
  一次并成功退出；下一次轮询由宿主负责，脚本不 sleep 或自行循环调度。
- **stream**：用已确认的游标连接并认证来源，再发初始空事件 checkpoint。
  后续来源记录满足条件时 emit，否则 checkpoint 已处理的位置；SDK 等待
  宿主 ACK 后才能继续推进。来源断开或失败时显式退出，由宿主按已接受进度恢复。

`state` 和 `cursor` 来自最后被宿主确认的进度，读取后修改内存副本不会保存。
将新值明确传入 emit/checkpoint。恢复游标表示接续旧观察，不是重新做初始基线；
不能仅因某条记录是重启后的第一条，就忽略它或推进游标跳过它。

## 试运行的边界

未注册脚本的示例：

```json
{"action":"check","source":"sentinel","script_path":"watchers/source-observer/main.py","mode":"poll","timeout_seconds":10}
```

来源需要网络时，仅在已有授权和部署能力允许时明确传 `network: true`；正式
创建也需要同样的网络选择。试运行真实执行脚本，不是静态检查或外部只读保证。
脚本的工作区与封存包受既有文件访问约束，日志写 stderr，避免输出凭据。

已有哨兵使用工具返回的 ID：

```json
{"action":"check","source":"sentinel","task_id":"sentinel:example-watch-id","timeout_seconds":10}
```

将示例 ID 替换为回执中的完整 `task_id`，不再额外添加前缀。此形式复用原封存
脚本、状态、游标、参数和网络设置，不能同时覆盖这些字段。
试运行最长 30 秒；它不注册或启用任务、不提交正式 state/cursor、不结算真实
事件，也不唤醒 Agent。stream 仅验证收到首个合法帧，不证明完整 ACK 循环。
试运行回执的 `registered/enabled: false` 表示本次操作没有注册或启用任务，
不代表已有任务被暂停；已有任务的真实状态以 `status` 查询为准。

检查实际回执：

- 首帧有效且 events 为空：协议帧已验证，本次没有待报告事件。
- 首帧包含事件：检查事件是否对应真实观察与目标条件；样例输出不是独立验证。
- 静默来源超时、没有合法帧：仍未完成验证；按情况修复初始 checkpoint、来源
  连接或脚本。不要用伪造业务事件掩盖静默，也不靠反复延长等待宣称通过。
- 脚本失败、协议损坏、取消或来源不可读：保留错误事实，不报告“没有变化”。

一次通过不证明整个业务目标或长期恢复可靠。仅在任务确实要求时，用受控来源
验证触发、不触发、重复事件或恢复，不为普通创建请求另建无关测试系统。

## 事件身份、完整性与正式注册

事件 key 表示稳定的来源事件或版本。同一个 key 的 summary/data 必须保持相同；
重试使用同 key，真正的新事件使用新 key。不要给旧事件加当前时间来制造新事件，
也不要维护无限增长的去重列表。使用来源的持久游标；确需历史时使用有界 SDK
history，容量不足明确失败，不驱逐仍有语义价值的记录或重置游标。

将“首次触发”“每次变化”“恢复后再次触发”等用户语义明确写进状态契约。
任务生命周期内仅首次触发时，需持久保存已触发标记，不能只检测每次越线，
也不在脚本重启时将标记重置。试运行不提交该标记；正式进度仍等待宿主确认。

无法完整观察、输入仍在写入、达到容量上限或缺少必要字段时，明确报告未完成，
保留最后已确认的消费位置。不能把截断的结果当完整总量，或将读取失败变成 0。
SDK 的 `fail` 使本次观察失败；不要捕获后再发一个“安静成功”的 checkpoint。

`create` 使用同一个脚本与业务目标；例如来源确实需要每分钟查询，且用户要求
开启并在一小时后停止：

```json
{"action":"create","source":"sentinel","title":"来源变化监测","task":"核对新增且符合用户条件的来源事件，完成所需分析后保存站内报告；无符合事件时保持安静。","script_path":"watchers/source-observer/main.py","mode":"poll","interval_seconds":60,"stop_after_seconds":3600,"enabled":true}
```

替换示例的条件、节奏、期限和授权选择，不把占位目标原样用于真实任务。
封存后修改工作区脚本不会自动替换已注册版本；需要更换时先核对当前任务、
已确认进度和可能已有的外部影响，再按用户授权显式注册新版本。
创建回执只确认宿主接收了委托，不能作为后续来源读取、业务处理或交付成功的证据。
