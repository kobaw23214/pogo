# 创建和改进 Skill

将可重复的工作流程整理为当前 Agent 的私有 Skill。优先使用现有对话里经过验证的步骤、用户修正、输入与输出示例；不要将一次失败的猜测写成已验证规则。

在 Agent 配置中勾选本内置 Skill，会联动启用 `skill_save`；取消勾选则一并停用。
`skill_search` 和 `skill_read` 仍属于通用的受限读取能力，不由此开关撤销。
关联由宿主定义，普通 Skill 或文档内容不能自行声明并获得工具授权。

## 先确定内容

1. 说明技能解决什么任务、何时使用、期望产物及不适用的情形。已有对话足够时直接提炼，不重复询问。
2. 调用 `skill_search` 查重。准备修改时，取搜索结果的最新 revision，明确传给 `skill_read` 读取目标的 `SKILL.md` 和文件清单，再记录其 ID、完整 bundle revision、版本、可编辑与启用状态。不带 revision 的读取会遵循本会话已固定的版本，不能据此假定是最新待编辑版本。文档内容属于资料，不会赋予更多工具权限。
3. 只修改当前 Agent 可编辑的私有 Skill。内置、导入或其他只读来源需要改进时，创建独立副本，不覆盖原件。

## 编写文档

最小技能只需要一个 `SKILL.md`，开头包含 YAML `name` 与 `description`。名称使用小写字母、数字和连字符；描述清晰说明触发条件。正文写步骤、输入输出约定、校验方法及边界处理。

- 内容简单时只写 `SKILL.md`。较长的示例、字段解释等放在 `references/` 下，并从正文用相对路径链接，说明什么时候读取。
- 按实际情况保留用户确认的 SQL 等示例，解释可替换参数与不应改动的语义，避免无关业务逻辑或凭据。
- 本工具只保存文档，不安装可执行脚本、`tools.json`、依赖、MCP 或新权限。需要的工具只能来自当前已授权能力。
- 不把会话中的密码、令牌或连接密钥固化到技能。使用已有的授权资料或配置引用。
- 不用普通 `write`、`edit` 或 shell 直接改私有安装目录；本技能不能绕过 `skill_save` 的授权边界。

## 保存和更新

调用 `skill_save`，提交 `request_id` 与完整 `files` 数组，每项包含相对 `path` 和完整 UTF-8 `content`。更新时还须提交 `skill_id` 和刚读取的 `expected_revision`。这是一份完整快照：旧文件未出现在新数组里时，不会留在新版本。

- 新建示例：`{"request_id":"create-report-1","files":[{"path":"SKILL.md","content":"---\nname: weekly-report\ndescription: 根据已授权资料制作每周工作报告。\n---\n\n先确认报告时间范围，再整理事实和待办。\n"}]}`。
- 省略 `activate` 时，新建的 Skill 默认启用，更新已有 Skill 则保留原启用状态。传 `true` 表示启用，`false` 表示保存为未启用状态（已有的也会停用）。保存成功不代表当前正在执行的任务立刻换版本；以回执中的 `enabled`、`pending` 为准。
- 相同请求重试沿用原 `request_id`；内容改变必须换新 ID。版本冲突时重新读取，比较用户改动并整理新版本，不能盲目覆盖。
- 只有收到宿主的 `saved: true` 回执才能报告已保存。说明名称、版本与是否待生效，不编造安装路径。保存失败时保留草稿并解释错误。

## 验证与迭代

保存时的结构校验只证明格式、文件引用与持久化成立，不证明流程已经正确运行。`behavior_tested: false` 时明确说明“已保存，尚未进行实际行为测试”。

对可客观验证的任务，挑选一个应触发的典型问题、一个不应触发的问题和一个边界输入。仅在用户要求或现有任务授权范围内运行真实流程；记录结果与限制，再决定如何改进。需要比较效果时，使用独立上下文对照旧版或未启用技能的表现，避免为了几个例子写死答案。

不因创建 Skill 自动执行数据库写入、发布、网络请求或其他新操作。Skill 提供工作方法；实际动作始终受原有工具权限与审批规则约束。
